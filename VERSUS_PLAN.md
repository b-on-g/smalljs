# smalljs / versus — интерактивное сравнение фреймворков

Раздел сайта smalljs. Референс подачи — https://1vs1.site/gpu ( сравнение видеокарт ): выбрал два → нажал → увидел разницу.

Модуль: `bog/smalljs/versus/` → `$bog_smalljs_versus`.

## Откуда взялось

Обсуждение с Иваном Горчаковым. Его тезисы, которые задают все требования ниже:

1. Словами и статьями никого не убедить. Убеждает собственный опыт: нажал сам — увидел сам.
2. Путь «ссылка → текст → таблица → надо читать → надо верить» не работает. Нужен путь «ссылка → сразу действие → результат».
3. Не говорим, что React и Vue — говно. Вообще ничего не доказываем и не комментируем. Показываем поведение, вывод человек делает сам.
4. Сухие цифры бенчмарков ( js-framework-benchmark ) человеку без погружения не говорят ничего. Нужен UX-слой, переводящий метрики в понятный опыт.
5. Интерактивность повышает ценность информации в глазах юзера: «я нажал кнопочки, я потратил усилие — буду читать внимательнее».
6. Не должно быть признаков накрутки.

Кирилл добавил: краевые случаи и количество кода — главное; читаемость видно сразу по коду.

## Решения ( приняты )

- **Размещение:** раздел внутри smalljs, а не отдельный сайт. Роутинг, SEO-мета, prerender, i18n и темы переиспользуются.
- **MVP:** сначала живые краш-тесты. Статические таблицы метрик — вторым заходом.
- **Метрики, где $mol проигрывает, включаем** отдельной категорией «Экосистема и рынок».

### Про доверие

Размещение внутри smalljs ослабляет аргумент «нет признаков накрутки» — сайт всё-таки про $mol. Компенсируем механикой, а не словами:

- методика и все исходники замеров — в публичном репо, ссылка с каждой метрики;
- у каждой цифры: значение, единица, дата замера, источник, ссылка «воспроизвести»;
- замеры прогоняются в открытом CI, а не руками;
- категория «Экосистема и рынок», где $mol честно красный;
- нет общего балла «победитель» — только «X лучше в N категориях из 7»;
- формулировки нейтральные: «показана карточка #3, данные пришли от #1», а не «React сломался».

## Структура ( копируем 1vs1.site )

```
Топ-нав smalljs: + пункт «Сравнить»

/smalljs/section=versus
  [ поле поиска ]  vs  [ поле поиска ]     ← выше сгиба только это
  «Популярные сравнения» — 9 готовых пар
  «Лучшие для SPA» / «Лучшие для сайтов» — карточки-топы по 6
  Таблица рейтинга: №, лого, название, балл, год выхода

/smalljs/section=versus/a=react/b=mol
  Шапка: два лого, вердикт «X лучше в 4 категориях из 7»
  Живой краш-тест — первым блоком, до всех таблиц
  Категории с характеристиками: значение A | бар | значение B | «быстрее на 62%»
  Side-by-side код одной и той же фичи
  Футер: методика, форма «предложить фреймворк»
```

Вход с лендинга — блоком **ниже первого экрана**, не в шапке ( прямая просьба Ивана: «можно ниже, но не в нос» ).

## Категории сравнения

### 1. Краевые случаи — ядро раздела

Каждый пункт — живое демо: 2–3 iframe рядом, один сценарий, одна кнопка «Запустить», индикатор ✅/⚠️/❌ и строка «что увидит пользователь». Это единственная категория, которой нет ни в одном существующем бенчмарке, и единственная, которая работает без чтения.

**В MVP ( 4 кейса × React / Vue / $mol ):**

1. **Гонка async-запросов** ( `race` ). Быстро кликаем по списку → ответ на старый запрос перезаписывает свежий. Видно: открыта карточка #5, данные от #1.
2. **Виртуализация нерегулярного контента** ( `virtual` ). Список из 10 000 элементов разной высоты, счётчик DOM-узлов.
3. **Утечка на подписках** ( `leak` ). 100 циклов монтирования → счётчик живых слушателей и heap.
4. **Ошибка в одном компоненте роняет всё дерево** ( `crash` ). Одна битая карточка из 20 → сколько выжило.

Точные шаги каждого сценария — в [versus/SPEC.md](./versus/SPEC.md).

Изначально четвёртым кейсом была **потеря ввода при обновлении**. Заменён на `crash`: у `$mol_string` есть известный баг с записью выделения обратно в DOM, и кейс про ввод может выстрелить в нас же. Из бэклога его не выкидываем — делать надо, честно, вместе с нашим багом.

**Дальше:**

- потеря ввода и позиции каретки при обновлении данных ( см. выше )
- отмена запроса при размонтировании
- двойной вызов эффекта
- каскадный ререндер: правка одного поля перерисовывает всё дерево
- потеря состояния при смене ключа в списке
- waterfall зависимых запросов
- восстановление позиции скролла
- состояние в URL: deep-link и кнопка «назад»
- поведение офлайн / при обрыве соединения

**Честность формулировок.** React и Vue в каждом кейсе пишутся так, как пишут по умолчанию, — и под каждым iframe подписано, что именно нужно дописать руками, чтобы артефакта не было ( флаг отмены, `unsubscribe`, библиотека виртуализации, `ErrorBoundary` ). Мы показываем цену дефолта, а не утверждаем, что починить нельзя.

### 2. Код

| Метрика | Источник |
|---|---|
| LOC на эталонную фичу | наши реализации, `bog/todomvc-compare/` |
| Файлов на фичу | там же |
| Прямых / транзитивных npm-зависимостей | `npm ls` |

Читаемость числом не меряем — показываем два блока кода рядом.

### 3. Вес и загрузка

Бандл raw / gzip / brotli, отдельно вес фреймворка и вес прикладного кода, TTI на throttled 3G, Lighthouse performance.

### 4. Скорость

Из форка js-framework-benchmark ( https://nin-jin.github.io/js-framework-benchmark/webdriver-ts-results/table.html ), JSON'ом, без перезамера: create 1k / 10k, replace all, partial update, select row, swap rows, remove row, append 1k, clear. Память: ready / after 1k / after 10k / after clear. Startup: TBT, main-thread work.

### 5. Из коробки — матрица да/нет

Роутер, i18n, темы, виртуализация, offline/PWA, SSR/prerender, тесты без DOM, DI, формы, типизация шаблонов, dev-server, кодогенерация.

### 6. Экосистема и рынок

Вакансии ( hh.ru, раз в квартал ), звёзды GitHub, npm downloads/мес, вопросов на StackOverflow, готовых UI-китов, год выхода, частота релизов, число мейнтейнеров. Здесь $mol проигрывает, и это показывается наравне с остальным.

### 7. Стоимость владения

Известные CVE в дереве зависимостей ( osv.dev ), breaking-релизов за 3 года, оценка миграции между мажорами.

## UX-слой поверх цифр

Три уровня на каждую метрику:

1. **Сырое значение** — `45 мс` / `120 мс`
2. **Относительное** — бар + «быстрее на 62%»
3. **Человеческий перевод** — «при скролле длинного списка пользователь заметит подтормаживание»

Балл 0–100 внутри каждой категории ( нормализация по лучшему ). Общего балла нет.

## Техника

- **Кейсы** — статические мини-сборки в `versus/cases/<case>/<fw>/`, грузятся в iframe. React и Vue **вендорить UMD-бандлами**: `require('react')` в MAM затащит весь пакет в основной бандл.
- **Замеры внутри iframe** ( FPS, память, счётчики ) — наружу через `postMessage`.
- **Данные** — `versus/data/*.json`, поля: `value`, `unit`, `source`, `measured_at`, `method_url`.
- **Роутинг** — существующий `$bog_builderui_router`; добавить `versus` в `section()`, `route_args()`, `meta()`, `body_content()` в `app/app.view.ts` и пункт в `$bog_smalljs_top`.
- **SEO** — на каждую пару своя `meta()`; URL `/smalljs/section=versus/a=react/b=mol` уже crawlable. Весь трафик такого сайта поисковый по запросам «X vs Y», это основной канал.

## Этапы

| Этап | Что | Оценка |
|---|---|---|
| 1 | Каркас раздела + движок краш-тестов + 4 кейса × 3 фреймворка | 5–7 дней |
| 2 | Селектор «A vs B», страница пары, категории 2–6 на статических данных | 3–4 дня |
| 3 | Side-by-side код | 2 дня |
| 4 | Остальные фреймворки и кейсы, топы, популярные сравнения | итеративно |

Фреймворки: старт с React, Vue, $mol ( ровно те, что назвал Иван ). Дальше Svelte, Solid, Angular, Qwik, Lit, Preact, Alpine, HTMX, Vanilla как базовая линия. Незаполненные — с явной пометкой «данных нет», а не с прочерком.

## Решённые вопросы

- **Тексты — EN-first**, как у остального smalljs. Локализация отдельной задачей позже, все строки уже через `@ \Text`.
- **Отдельный публичный репо под методику не нужен** — методика и сценарии живут в `bog/smalljs/versus/`, ссылка на них стоит в блоке «How this is measured» внизу раздела. Репозиторий сайта и так открыт, отдельный ничего к проверяемости не добавляет.
