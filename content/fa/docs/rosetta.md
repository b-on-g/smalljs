# از React، Vue و Svelte

اگر با React، Vue یا Svelte رابط ساخته‌اید، بیشترِ آنچه $mol انجام می‌دهد را از پیش می‌فهمید — فقط نام‌ها فرق دارند. این فریم‌ورک‌ها به دلایلِ خوبی عالی و محبوب‌اند؛ این صفحه یک جدولِ ترجمه است، نه یک رقابت، تا کمک کند سریع احساسِ راحتی کنید.

## نقشهٔ مفاهیم

| ایده | React | Vue | Svelte | $mol |
|------|-------|-----|--------|------|
| کامپوننت | تابع / کلاس | SFC (`.vue`) | فایلِ `.svelte` | `.view.tree` + `.view.ts` |
| وضعیتِ محلی | `useState` | `ref` / `reactive` | `let x` | `@ $mol_mem` |
| مقدارِ مشتق | `useMemo` | `computed` | `$: y = …` | `@ $mol_mem` (سلول‌های دیگر را می‌خواند) |
| اثرِ جانبی | `useEffect` | `watchEffect` | `$: { … }` | `@ $mol_action` (صریح، هرگز خودکار نیست) |
| Props | props | props | `export let` | اتصال‌ها در `view.tree` |
| رویداد | `onClick` | `@click` | `on:click` | `click? <=> handler?` |
| ورودیِ دوطرفه | ورودیِ کنترل‌شده | `v-model` | `bind:value` | `value? <=> field?` |
| فهرست | `items.map()` | `v-for` | `{#each}` | `Row*`ِ کلیددار |
| شرط | `cond && …` | `v-if` | `{#if}` | برای حذف، `null` انتساب دهید |
| وضعیتِ مشترک | Redux / Context | Pinia / provide | store‌ها | هر شیئی با `@ $mol_mem` |
| مسیریابی | React Router | Vue Router | SvelteKit | `$mol_state_arg` |
| استایل‌دهی | CSS-in-JS | `<style>`ِ اسکوپ‌دار | `<style>` | `.view.css.ts`ِ نوع‌دار |

## چیزهایی که معمولاً تازه به نظر می‌رسند

- **واکنش‌گرایی خودکار است و اختیاری نیست.** مانندِ `ref`ِ Vue یا `$:`ِ Svelte، یک مقدارِ `@ $mol_mem` خودش خواننده‌هایش را به‌روز می‌کند — اما هیچ آرایهٔ وابستگی‌ای برای نگهداری و هیچ اشتراکِ دستی‌ای در هیچ‌جا نیست.
- **افکت‌ها از محاسبه‌ها جدا هستند.** React مشتق‌گیری و افکت‌ها را در هوک‌ها درهم می‌تند؛ $mol آن‌ها را جدا نگه می‌دارد: `@ $mol_mem` فقط محاسبه می‌کند، `@ $mol_action` افکت‌ها را انجام می‌دهد. همین جداسازی است که بیشترِ معماهای «چرا این دو بار اجرا شد؟» را برمی‌دارد.
- **وضعیت فقط شیء است.** هیچ کتابخانهٔ storeِ اختصاصی‌ای برای پذیرفتن نیست — یک مقدارِ مشترک یک ویژگیِ واکنش‌گرا روی هر شیئی است، پس وضعیتِ سراسری و وضعیتِ کامپوننت یکسان کار می‌کنند.

## تو حل می‌کنی یا فریم‌ورک

تفاوت عمیق‌تر در واژگان بالا نیست — بلکه در این است که *چه کسی* مشکلات تکرارشونده را حل می‌کند. در React، Vue یا Svelte بیشتر آن‌ها الگوهایی هستند که در هر کامپوننت دوباره پیاده‌سازی می‌کنی و به شیوهٔ خودت خراب می‌کنی. در $mol آن‌ها ویژگی‌های یک سازوکار واحد هستند، بنابراین کل این دسته از کار به‌جای گرفتن یک API بهتر، ناپدید می‌شود.

- **انبار وضعیت** — پنج زیرسیستم ذخیره‌سازی در React (‏Redux + RTK Query + `useState` + `useReducer` + Context) به یکی فرومی‌ریزند: فیلدهای واکنش‌گرا روی کامپوننت.
- **واکنش‌گرایی** — جای دیگر از بیرون سنجاق شده (MobX، signals)؛ اینجا در پی قرار دارد، پس چیزی لازم نیست خود را ثبت کند.
- **جداسازی خرابی** — `<ErrorBoundary>` که با دست گذاشته می‌شود در برابر اینکه هر کامپوننت به‌طور پیش‌فرض مرز خودش است.
- **افکت‌ها** — یک چک‌لیست `useEffect`/`useMemo`/deps در ده‌ها سناریو در برابر یک متد، یا متدی با یک action. یک انشعاب در درخت، نه دوازده تا.
- **مجازی‌سازی** — یک کامپوننت جانبی برای هر فهرست در برابر اینکه هر چیز بیرون از viewport اصلاً وجود ندارد.

جایی که جدول بالا فقط چیزها را تغییر نام می‌دهد، اینجا جایی است که $mol واقعاً آن‌ها را حذف می‌کند.
