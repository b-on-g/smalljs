# ابزارها

$mol در هر ویرایشگری کار می‌کند، اما مجموعه‌ای کوچک از ابزارها کار با `.view.tree` و سبک‌های نوع‌دار را بسیار راحت‌تر می‌کند: یک اسکافولدر پروژه، یک زبان‌سرور، یکپارچه‌سازی‌های ویرایشگر برای Zed و VS Code، و یک مهارت که فریم‌ورک را به دستیارهای LLM می‌آموزد.

## اسکافولد کردن یک پروژه

`create-view-tree-lsp` یک ماژول $mol آمادهٔ اجرا تولید می‌کند تا مجبور نباشید کد قالبی را با دست کنار هم بچینید:

```bash
npx create-view-tree-lsp bog/myapp
```

آرگومان همان مسیر ماژول است (`namespace/name` یا معادل آن `bog_myapp`). این دستور `view.tree`، `view.ts`، `view.css.ts` و `index.html` یک برنامهٔ کارآمد را می‌نویسد، به‌علاوهٔ GitHub Actions برای استقرار آن. به‌طور پیش‌فرض یک ذخیره‌گاه local-first به نام **Giper Baza**، یک پیکربندی **Docker** و یک پوستهٔ دسکتاپ **Tauri** را نیز شامل می‌شود. هرکدام را می‌توانید با یک پرچم خاموش کنید:

```bash
npx create-view-tree-lsp bog/myapp --no-baza --no-docker --no-tauri
```

در عوض، چند بخش اختیاری‌اند و باید فعالشان کرد:

- `--backend` یک بک‌اند REST به نام `$mol_server` با ذخیره‌سازی `node:sqlite` و یک نوع آیتم TypeScript مشترک اضافه می‌کند
- `--prerender` و `--seo` دیده‌شدن در موتورهای جست‌وجو را اضافه می‌کنند، که در پایین زیر بخش [یکپارچه‌سازی مداوم](#!section=docs/page=tooling/Docs.Body=%DB%8C%DA%A9%D9%BE%D8%A7%D8%B1%DA%86%D9%87%E2%80%8C%D8%B3%D8%A7%D8%B2%DB%8C%20%D9%85%D8%AF%D8%A7%D9%88%D9%85) توضیح داده شده‌اند

اسکافولدر یک پوشش نازک روی CLI موجود در زبان‌سرور است، بنابراین `npx view-tree-lsp create bog/myapp` همان کار را مستقیماً انجام می‌دهد.

## پخش‌کردن ترجمه‌ها میان ماژول‌ها

مترجم یک فایل می‌خواهد، نه سی تا. برنامهٔ ساخته‌شده همین حالا چنین فایلی دارد: در `<app>/-/web.locale=<lang>.json` همهٔ رشته‌های همهٔ ماژول‌هایی که برنامه بسته‌بندی می‌کند جمع است. آن را بفرستید، ترجمه‌شده تحویل بگیرید و دوباره میان ماژول‌ها پخش کنید:

```bash
# از ریشهٔ MAM
npx view-tree-lsp locale bog/myapp/app/- --exclude=mol --update
```

هر کلید مسیر ماژول خودش را با خود دارد، بنابراین `$my_page_greeting` در `my/page/page.locale=<lang>.json` می‌نشیند، کنار همان منبعی که به آن تعلق دارد. آرگومان می‌تواند یک پوشه باشد یا یک فایل زبان.

- `--include=<تکه‌ای از مسیر>` — فقط ماژول‌هایی که مسیرشان آن تکه را دارد؛ می‌توان چند بار آورد
- `--exclude=<تکه‌ای از مسیر>` — از آن‌ها بگذر؛ `--exclude=mol` بسته‌های خودِ فریم‌ورک را دست‌نخورده می‌گذارد
- `--update` — با فایل‌های موجود ادغام کن: مقدارهای ورودی برنده‌اند و کلیدهایی که در ورودی نیستند می‌مانند
- `--dry` — نقشهٔ کار را چاپ کن و چیزی ننویس

پیدا کردن ماژول از روی کلید ظریف‌تر از آن است که به نظر می‌رسد. `_` هم پوشه‌ها را جدا می‌کند و هم واژه‌ها را، پس «طولانی‌ترین مسیرِ منطبق» پاسخ درست نیست: در `$my_page_lang_hint` نام ویژگی با `lang` آغاز می‌شود و اگر واقعاً زیرماژولی به نام `my/page/lang` کنارش باشد، کلید را می‌بلعد. برای همین فرمان از هر ماژولِ نامزد می‌پرسد چه کلیدهایی را اعلام کرده است — MAM دقیقاً همان‌ها را در `<module>/-view.tree/*.locale=en.json` می‌نویسد — و کلید را به صاحب واقعی‌اش می‌سپارد.

## یکپارچه‌سازی مداوم

اسکافولدر GitHub Actions را در `.github/workflows/` می‌نویسد، پس یک پروژهٔ جدید بدون تنظیمات اضافی مستقر و منتشر می‌شود.

`deploy.yml` روی هر push اجرا می‌شود. برنامه را با `hyoo-ru/mam_build` می‌سازد، `app/-` را از `main` روی **GitHub Pages** منتشر می‌کند، و به هر شاخهٔ `feature/*` پوشهٔ پیش‌نمایش مخصوص خودش را می‌دهد — که هنگام حذف شاخه به‌طور خودکار برداشته می‌شود.

### SEO

دو گزینهٔ مستقل، هر دو با برچسب‌های `v*` فعال می‌شوند:

- **`--prerender`** صفحه‌هایی را که فهرست می‌کنید (مانند `home`) با `b-on-g/mol-prerender-action` به HTML ایستا رندر می‌کند، تا خزنده‌ها و پیش‌نمایش‌های پیوند محتوای واقعی را ببینند.
- **`--seo`** رانتایم `$bog_seo` را اضافه می‌کند: یک مسیریاب بر پایهٔ pathname همراه با نقشهٔ سایت، `robots.txt`، `llms.txt` و تزریق متادیتا برای هر صفحه. این کار بیلد را سرو می‌کند، HTML پیش‌رندرشدهٔ متعارف را استخراج می‌کند و آن را دوباره در استقرار می‌گنجاند.

وقتی مشتی صفحهٔ عمومی باید قابل خزش باشند سراغ prerender action بروید، و وقتی به نقشهٔ سایت و متادیتای هر صفحه نیاز دارید سراغ `$bog_seo`.

### دسکتاپ Tauri

با گزینهٔ Tauri، `tauri.yml` باینری‌های دسکتاپ را روی برچسب‌های `v*` (یا بنا به درخواست) از طریق ورک‌فلوی قابل‌استفادهٔ مجدد `b-on-g/tauri-mol-workflow-template` می‌سازد، از همان ماژولی که روی وب مستقر می‌کنید.

## زبان‌سرور

`view-tree-lsp` یک پیاده‌سازی Language Server Protocol برای قالب `view.tree` است. آن را بنا به درخواست با npx اجرا کنید، بدون نیاز به نصب سراسری:

```bash
npx view-tree-lsp@latest
```

فضای کاری شما را پویش می‌کند و به هر ویرایشگر توانمند در LSP این‌ها را می‌دهد:

- تکمیل خودکار برای مؤلفه‌های `$mol_*` و مؤلفه‌ها و ویژگی‌های تعریف‌شده در پروژهٔ خودتان
- پیشنهاد ویژگی محدود به مؤلفهٔ زیر مکان‌نما
- طرح کلی از اعلان‌های مؤلفه برای ناوبری
- به‌روزرسانی زنده همزمان با تغییر فایل‌ها

چون به LSP سخن می‌گوید، می‌توانید language-client هر ویرایشگری را به `npx view-tree-lsp` نشانه بگیرید. دو یکپارچه‌سازی زیر آن را برای شما سیم‌کشی می‌کنند.

## Zed

افزونهٔ **View Tree Syntax Highlighting for $mol** گرامر tree-sitter، زبان‌سرور و یک تم آیکون اختیاری را با هم بسته‌بندی می‌کند. آن را از مدیر افزونهٔ Zed نصب کنید:

1. پالت فرمان را باز کنید (`Cmd+Shift+P` / `Ctrl+Shift+P`)
2. **zed: extensions** را اجرا کنید
3. `view.tree` یا `mol` را جست‌وجو کنید و افزونه را نصب کنید

برجسته‌سازی نحوی، تکمیل خودکار و طرح کلی برای فایل‌های `.view.tree` را دریافت می‌کنید. [منبع](https://github.com/Dev-cmyser/zed-view.tree-mol-support) و یک [تم آیکون](https://github.com/Dev-cmyser/zed-viewtree-icon-theme) متناسب روی GitHub هستند.

## VS Code

فضای کاری MAM از پیش پیکربندی VS Code خود را همراه دارد. وقتی پوشهٔ کلون‌شدهٔ `mam` را باز می‌کنید، VS Code پیشنهاد می‌دهد افزونه‌های توصیه‌شده را از `.vscode/extensions.json` نصب کنید:

- `nin-jin.vscode-language-tree` — پشتیبانی زبان `view.tree`
- `stan-donarise.view-tree-language` — نحو و گرامر
- `editorconfig.editorconfig` — قالب‌بندی یکدست

همان پوشه `mol.code-snippets` را نیز عرضه می‌کند، پس اسنیپت‌های مؤلفه و بایندینگ بدون هیچ تنظیم اضافی در دسترس‌اند. درخواست را بپذیرید و فایل‌های `.view.tree` و TypeScript از همان ابتدا برجسته می‌شوند.

## مهارتِ LLM

`mol_skill` زمینه‌ای را که یک دستیار هوش مصنوعی برای نوشتن $mol لازم دارد فراهم می‌کند: نحوِ `view.tree`، ساختار ماژول MAM، تقسیمِ کار میان `view.ts` و `view.css.ts`، مدل‌سازی داده با Giper Baza و بسته‌بندی با Tauri. این فقط یک پوشهٔ مهارتِ ساده است، یک گردش‌کارِ `SKILL.md` به‌همراه راهنماهای مرجع، پس هر ابزار LLM که قالبِ skills را بخواند می‌تواند آن را بارگذاری کند، از جمله Claude Code و Cursor. با CLIِ skills نصبش کنید:

```bash
npx skills add b-on-g/mol_skill --all -g
```

سپس با زبان خودتان بپرسید («ساختار ماژول MAM»، «CRUD و نقش‌ها در Giper Baza») و دستیار پیش از پاسخ، مرجعِ مناسب را باز می‌کند، پس کدی که می‌نویسد از قراردادهای همین مستندات پیروی می‌کند. [سورس](https://github.com/b-on-g/mol_skill) روی GitHub است و اگر ترجیح می‌دهید خودتان بخوانید، فایل‌های مرجع به‌تنهایی هم کاملاً خوانا هستند.
