# مسیریابی

مسیریابی در $mol یک کتابخانهٔ جداگانه نیست — URL فقط تکه‌ای دیگر از وضعیت واکنش‌گراست. آن را بخوانید، بنویسید، و نماها همان‌طور واکنش نشان می‌دهند که به هر سلولی واکنش نشان می‌دهند. دکمهٔ بازگشت، پیوندهای عمیق و URLهای قابل‌اشتراک همه رایگان به دست می‌آیند.

## URL به‌عنوان وضعیت

`$mol_state_arg` پارامترهای URL را به‌عنوان مقادیر واکنش‌گرا در معرض دید قرار می‌دهد. یکی را به یک ویژگی متصل کنید و نوار نشانی به منبع حقیقت شما تبدیل می‌شود:

```typescript
namespace $.$$ {
	export class $my_app extends $.$my_app {
		@ $mol_mem
		page( next?: string ) {
			return $mol_state_arg.value( 'page', next ) ?? 'home'
		}
	}
}
```

خواندن `page()` مقدار کنونی را برمی‌گرداند؛ فراخوانی `page('about')` پیمایش می‌کند. هر چیزی که `page()` را می‌خواند هنگام تغییر دوباره رندر می‌شود — از جمله دکمهٔ بازگشت مرورگر، که سلول را برای شما به‌روز می‌کند.

## جابه‌جایی میان صفحه‌ها

یک مقدار مسیریابی‌شده را با یک `switch` ساده ترکیب کنید تا انتخاب کنید چه چیزی رندر شود. چون نماها [تنبل](#!section=docs/page=rendering) هستند، صفحه‌هایی که نشان نمی‌دهید هرگز ساخته نمی‌شوند:

```typescript
@ $mol_mem
body_content() {
	switch ( this.page() ) {
		case 'about': return [ this.About() ]
		case 'docs': return [ this.Docs() ]
		default: return [ this.Home() ]
	}
}
```

## پیوندهایی که آرگومان تنظیم می‌کنند

در `view.tree`، یک پیوند می‌تواند آرگومان‌های URL را به‌صورت اعلانی تنظیم کند — کلیک روی آن بدون هیچ هندلری پیمایش می‌کند:

```tree
<= About_link $mol_link
	arg *
		page \about
	sub / <= about_label \About
```

`$mol_link` وقتی آرگومان‌هایش با URL کنونی مطابقت داشته باشد خودش را نیز فعال (`mol_link_current`) علامت می‌زند، بنابراین برجسته‌کردن صفحهٔ کنونی به هیچ وضعیت اضافه‌ای نیاز ندارد.

## چند پارامتر

آرگومان‌ها مستقل‌اند، پس یک صفحه می‌تواند هم‌زمان بر اساس چند تا مسیریابی کند. همین سایت مستندات بر اساس هر دو `section` و `page` مسیریابی می‌کند:

```tree
<= Guide_link $mol_link
	arg *
		section \docs
		page \views
```

هر کلید از طریق URL رفت‌وبرگشت می‌کند، پس هر نمایی به‌طور ذاتی قابل‌اشتراک و قابل‌نشانه‌گذاری است. تنظیم یک آرگومان بقیه را دست‌نخورده می‌گذارد، که پیوندهای عمیق را — یک بخش *و* صفحه *و* لنگرِ مشخص — صرفاً به مسئلهٔ تنظیم کلیدهایی که برایتان مهم‌اند تبدیل می‌کند.

## وضعیتی که نباید در URL باشد

هر تکه از وضعیت به نوار نشانی تعلق ندارد. برای مقادیری که باید به‌صورت محلی پایدار بمانند اما پیوندها را آلوده نکنند — یک نوار کناریِ جمع‌شده، یک پیش‌نویس — از `$mol_state_local` استفاده کنید که با همان شکلِ getter/setter در `localStorage` ذخیره می‌کند:

```typescript
@ $mol_mem
sidebar_open( next?: boolean ) {
	return $mol_state_local.value( 'sidebar_open', next ) ?? false
}
```

وقتی وضعیت باید قابل‌اشتراک باشد سراغ `$mol_state_arg` بروید؛ وقتی فقط باید به‌خاطر سپرده شود سراغ `$mol_state_local`.

## بعدی

دیدید که $mol چگونه وضعیت را به UI و URL تبدیل می‌کند. در [رندر](#!section=docs/page=rendering) ببینید همهٔ این‌ها چگونه به‌طور کارآمد به صفحه می‌رسند.
