# Установка

[Быстрый старт](#!section=docs/page=getting-started) проведёт вас через первое приложение шаг за шагом. Эта страница — справочник: как устроен $mol-проект и как работает сборка.

## Требования

- **Node.js 24+** и **git**. Ничего больше глобально не ставится.

## Воркспейс MAM

$mol-приложения живут внутри **MAM** — инструмента сборки и реестра модулей. Вы клонируете его один раз и разрабатываете свои модули внутри:

```bash
git clone https://github.com/hyoo-ru/mam.git ./mam
cd mam
npm install
npm start
```

`npm start` поднимает следящий дев-сервер на `http://localhost:9080/`. Он пересобирает при сохранении и разрешает зависимости автоматически — вам не нужно поддерживать конфиг сборщика.

Есть и официальный быстрый старт из [README MAM](https://github.com/hyoo-ru/mam#quick-start), без клонирования:

```bash
mkdir mam && cd mam
npm exec mam@latest
```

Он поднимает тот же дев-сервер в пустой папке. Мы всё же советуем клон: вся работа всё равно идёт внутри MAM, а в клоне сразу есть настройки редактора (`.vscode`) и `.npmrc`.

## Как именуются модули

Каждое имя компонента соответствует пути к папке, и **каждое подчёркивание — разделитель папок**:

```
$my_app          →  my/app/
$my_app_header   →  my/app/header/
```

Имена папок-модулей никогда не содержат подчёркивания — для составных имён используйте вложенные папки. Если используемый компонент никак не попадает в бандл, почти всегда путь к папке не совпадает с именем класса.

## Анатомия модуля

Компонент — это папка с файлами. Основные:

| Файл | Назначение |
|------|-----------|
| `name.view.tree` | Декларативная разметка |
| `name.view.ts` | Поведение (TypeScript) |
| `name.view.css.ts` | Типизированные стили |
| `index.html` | Точка входа для модуля-приложения |
| `name.view.css` | Сырой CSS: `@keyframes`, `content`, значения CSS-переменных |
| `name.test.ts` | Тесты |
| `name.meta.tree` | Мета модуля: файлы для `deploy`, дополнительные паки |

`index.html` приложения монтирует корневой компонент:

```html
<body mol_view_root>
	<div mol_view_root="$my_app"></div>
	<script src="web.js"></script>
</body>
```

## Сборка для продакшена

Дев-сервер собирает на лету, но любой модуль можно собрать явно из корня воркспейса:

```bash
npm start my/app
```

Результат оказывается в `my/app/-/` — включая `web.js`, `web.css` и `web.audit.js`. **Всегда проверяйте аудит:** чистый `web.audit.js` означает отсутствие неиспользуемых зависимостей и ошибок типов.

## Подключение npm-пакетов

Сошлитесь на пакет через `require`, и MAM установит его при следующей сборке и положит в бандл:

```typescript
const dayjs = require( 'dayjs' ) as typeof import( 'dayjs' )
```

### Загрузка пакета в рантайме

Тяжёлой библиотеке, которая нужна одному экрану, не обязательно лежать в `web.js`. Положите её готовый браузерный файл рядом с бандлом и загружайте при первом обращении.

Укажите файл в `meta.tree` модуля:

```tree
deploy \/node_modules/@turf/turf/turf.min.js
```

`deploy` установит пакет, если его нет, и скопирует файл в `-/node_modules/@turf/turf/turf.min.js` — и на дев-сервере, и в продакшен-сборке. Загружайте его через `$mol_import.script`:

```typescript
namespace $ {
	export class $my_app_turf extends $mol_object {

		@ $mol_mem
		static api() {
			$mol_import.script( './node_modules/@turf/turf/turf.min.js' )
			return ( globalThis as any ).turf as typeof import(
				'@turf/turf'
			)
		}

	}
}
```

- Путь относительный и разрешается от страницы в `-/`, поэтому один и тот же код работает на дев-сервере, в `test.html` и при деплое в подпапку. Ведущий `/` работает, только пока приложение лежит в корне домена.
- `$mol_import.script` приостанавливает фибру до загрузки скрипта и кеширует по URL: файл скачивается один раз, а всё, что читает `$my_app_turf.api()` внутри `$mol_mem`, просто ждёт его.
- Глобальное имя, здесь `turf`, — то, которое назначает браузерная сборка библиотеки. Какое именно, написано в её README.
- `typeof import( … )` даёт полную типизацию. Держите имя пакета на отдельной строке: сборщик считает зависимостью `require( '…' )` и `import( '…' )`, записанные в одну строку, и всё-таки положит весь пакет в `web.js`.
