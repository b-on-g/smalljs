# Из React, Vue и Svelte

Если вы собирали интерфейсы на React, Vue или Svelte, вы уже понимаете большую часть того, что делает $mol — просто названия другие. Эти фреймворки отличные и популярны заслуженно; эта страница — таблица перевода, а не соревнование, чтобы вы быстрее почувствовали себя как дома.

## Карта концепций

| Идея | React | Vue | Svelte | $mol |
|------|-------|-----|--------|------|
| Компонент | функция / класс | SFC (`.vue`) | файл `.svelte` | `.view.tree` + `.view.ts` |
| Локальное состояние | `useState` | `ref` / `reactive` | `let x` | `@ $mol_mem` |
| Производное значение | `useMemo` | `computed` | `$: y = …` | `@ $mol_mem` (читает другие ячейки) |
| Побочный эффект | `useEffect` | `watchEffect` | `$: { … }` | `@ $mol_action` (явный, никогда не автоматический) |
| Пропсы | props | props | `export let` | связывания в `view.tree` |
| Событие | `onClick` | `@click` | `on:click` | `click? <=> handler?` |
| Двустороннее поле | controlled input | `v-model` | `bind:value` | `value? <=> field?` |
| Список | `items.map()` | `v-for` | `{#each}` | ключевое `Row*` |
| Условие | `cond && …` | `v-if` | `{#if}` | присвоить `null`, чтобы убрать |
| Общее состояние | Redux / Context | Pinia / provide | stores | любой объект с `@ $mol_mem` |
| Роутинг | React Router | Vue Router | SvelteKit | `$mol_state_arg` |
| Стили | CSS-in-JS | scoped `<style>` | `<style>` | типизированный `.view.css.ts` |

## Что обычно ощущается новым

- **Реактивность автоматическая и необязательной не бывает.** Как `ref` во Vue или `$:` в Svelte, значение `@ $mol_mem` само обновляет своих читателей — но нет массива зависимостей, который надо поддерживать, и нигде нет ручной подписки.
- **Эффекты отделены от вычислений.** React складывает вывод и эффекты в хуки; $mol держит их порознь: `@ $mol_mem` только вычисляет, `@ $mol_action` выполняет эффекты. Именно это разделение убирает большинство загадок «почему это выполнилось дважды?».
- **Состояние — это просто объекты.** Нет отдельной библиотеки стора, которую надо принимать — общее значение это реактивное свойство на любом объекте, поэтому глобальное состояние и состояние компонента работают одинаково.

## Решаешь ты или решает фреймворк

Разница глубже, чем словарь выше — важно, *кто* решает повторяющиеся проблемы. В React, Vue и Svelte это паттерны, которые ты переписываешь в каждом компоненте и по-своему ломаешь. В моле это свойства одного механизма, поэтому целый класс работы не получает удобный API, а просто исчезает.

- **Стор** — пять подсистем хранения в React (Redux + RTK Query + `useState` + `useReducer` + Context) сворачиваются в одну: реактивные поля компонента.
- **Реактивность** — в других местах прикручена сверху (MobX, signals), тут лежит в основании, включать ничего не надо.
- **Изоляция падений** — `<ErrorBoundary>` руками против того, что каждый компонент сам себе boundary по умолчанию.
- **Эффекты** — чек-лист `useEffect`/`useMemo`/deps на десяток сценариев против метода (или метода с action). В дереве одна развилка, а не двенадцать.
- **Виртуализация** — сторонний компонент на каждый список против того, что вне вьюпорта ничего физически не существует.

Где таблица выше переименовывает — тут мол это просто убирает.
