# Релизы

$mol поставляется **непрерывно**. Вместо нарезки нумерованных версий фреймворк едет прямо из монорепозитория [mam_mol](https://github.com/hyoo-ru/mam_mol) — каждое смёрженное изменение немедленно доступно всем, кто на нём строит. Инструмент сборки MAM всегда тянет текущие исходники, поэтому нет ни шага обновления, ни матрицы версий, которую надо сводить.

## Как следить за изменениями

- **История коммитов** — [коммиты mam_mol](https://github.com/hyoo-ru/mam_mol/commits/master) это канонический changelog.
- **История по модулю** — папка каждого компонента на GitHub несёт собственный лог коммитов, так что можно следить только за теми частями, которые вы используете.
- **DEV-сообщество** — заметные добавления и разборы публикуются под [тегом #mol](https://dev.to/t/mol).

## Что это значит на практике

Поскольку нет ломающих релизных границ, фреймворк тяготеет к обратно совместимой эволюции: компоненты обретают возможности без переименований, а типизированные интерфейсы `view.tree` выводят несовместимости на этап компиляции, а не в рантайм. Если после обновления сборка перестала компилироваться, ошибки TypeScript укажут прямо на то, что изменилось.
