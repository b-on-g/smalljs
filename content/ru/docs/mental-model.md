# Ментальная модель

Если вы пришли из React или Vue, первые дни в $mol уходят на поиски того, чего тут нет: `computed`, `watch`, `useEffect`, `onMounted`, `fetch` в хуке жизненного цикла. Они не спрятаны где-то в API — для них просто нет места в модели. Эта страница — пятиминутная версия этой модели. Прочтите её перед [Вью](#!section=docs/page=views) и возвращайтесь, когда очередное знакомое имя не найдётся.

## Тянем, а не толкаем

Ничего не вычисляется, пока это кто-нибудь не прочитает. Вью рендерится, читая свои свойства; каждое свойство читает то, что нужно ему; цепочка зависимостей собирается из этих чтений сама. Нет подписки, которую надо объявить, и нет `watch`, который надо зарегистрировать: чтение и есть подписка.

```tree
$my_profile $mol_view
	sub /
		<= Name $mol_view
			sub / <= name \
```

```typescript
namespace $.$$ {
	export class $my_profile extends $.$my_profile {
		@ $mol_mem
		user() {
			return this.$.$mol_fetch.json( 'https://api.example.com/me' ) as { name: string }
		}
		name() {
			return this.user().name
		}
	}
}
```

Рендеринг `Name` читает `name()`, `name()` читает `user()`, `user()` идёт в сеть. Никто не рассказывал вью про запрос и никто не рассказывал запросу про вью. Когда `user()` меняется, пересчитывается всё, что его читало, и больше ничего.

## Никакого жизненного цикла

Нет ни `mounted`, ни `useEffect`, ни `created`. Данные запрашиваются чтением свойства, а свои свойства вью читает, когда рендерится. Поэтому пример выше загружает пользователя в тот момент, когда `$my_profile` появляется на экране, и не раньше. Когда вью уходит с экрана, `user()` больше никто не читает, и ячейка освобождается вместе с вью.

Это и есть вся замена паттерну «загрузить на маунте»: вью просит то, что ему нужно, а фреймворк решает, когда спрашивать. Загрузка привязана не к событию страницы, а к тому, что её видно.

## Свойство — это ячейка

Один метод с необязательным аргументом — сразу и геттер, и сеттер, и вычисляемое значение, и состояние:

```typescript
@ $mol_mem
count( next?: number ) {
	return next ?? 0
}
```

Вызов без аргумента читает, с аргументом — пишет. `@ $mol_mem` превращает метод в кешируемую ячейку, которая пересчитывается, когда изменилось что-то из прочитанного ею. Вычисляемое значение — это просто метод с `@ $mol_mem`, читающий другие методы. Наблюдатель не нужен: побочный эффект принадлежит событию, а обработчик события — это метод, помеченный `@ $mol_action`.

```typescript
@ $mol_mem
doubled() {
	return this.count() * 2
}

@ $mol_action
increment() {
	this.count( this.count() + 1 )
}
```

[Состояние и реактивность](#!section=docs/page=state) разбирает правила того, что позволено внутри каждого из двух.

## Синхронный код, который умеет ждать

`user()` выше выглядит синхронным и написан так, будто ответ уже есть. Это работает, потому что каждое вычисление выполняется в фибре. `this.$.$mol_fetch.json()` приостанавливает эту фибру, а фреймворк перезапускает вычисление, когда ответ пришёл. До тех пор вью, прочитавшее `user()`, показывает состояние загрузки; если запрос упал, то же вью показывает ошибку. Вы не пишете ни флага `isLoading`, ни `try`/`catch`.

Тот же механизм обслуживает любой асинхронный источник. [Загрузка данных](#!section=docs/page=data) проходит перезагрузку и обработку ошибок.

## Всё — переопределение

Файл `view.tree` — это список объявлений методов. Каждая строка под компонентом — его свойство со значением по умолчанию, и любое свойство вложенного компонента переопределяется прямо там, где он используется, одной строкой. Placeholder у текстового поля — это свойство `hint` у `$mol_string`:

```tree
$my_search $mol_view
	sub /
		<= Query $mol_string
			hint \Search
			value? <=> query? \
```

Нет списка пропсов, который надо расширять, нет обёртки, которую надо писать, и нет форка, который надо поддерживать. Если у компонента есть свойство, его можно задать снаружи.

## Как читать исходники

Предыдущий раздел поднимает главный вопрос: откуда вы знаете, что свойство называется `hint`? Ответ — вы смотрите, а фреймворк устроен так, чтобы смотреть было дёшево.

**Исходники фреймворка лежат рядом с вашими.** В воркспейсе MAM `mol/string/string.view.tree` — в соседней папке от `my/hello/`. Он не в `node_modules` и не внутри бандла; это такой же файл, какие вы пишете сами.

**Имя класса — это путь.** `$mol_string` живёт в `mol/string/`, `$mol_button_major` — в `mol/button/major/`. Каждое подчёркивание — разделитель папок, поэтому имя из вашего дерева всегда превращается в папку, которую можно открыть. Поддержка редактора со страницы [Инструментарий](#!section=docs/page=tooling) дописывает эти имена за вас.

**`.view.tree` компонента — это полный список его свойств со значениями по умолчанию.** Форма значения говорит о типе: `\` начинает строку, `/` — список, `*` — словарь, голое число — число, `true` и `false` — булевы, `null` означает отсутствие, а `<=` вводит под-вью или свойство, взятое у владельца. Вот та часть `mol/string/string.view.tree`, которая важна для поля ввода:

```tree
$mol_string $mol_view
	dom_name \input
	enabled true
	field *
		^
		disabled <= disabled false
		value <= value_changed? <=> value? \
		placeholder <= hint_visible <= hint \
	attr *
		^
		type <= type? \text
```

Прочтите вслух. `dom_name \input`: этот компонент рендерится элементом `input`. `enabled true`: булево свойство, включённое по умолчанию. `field *` — словарь полей DOM-элемента; имена слева принадлежат DOM, имена справа — компоненту, и то, что правее всех, вы и задаёте. Так DOM-овский `placeholder` берётся из `hint`, пустой строки по умолчанию; DOM-овский `value` — это записываемое свойство `value?`, а атрибут `type` — записываемое `type?`, по умолчанию `text`. Placeholder, выключенное поле и поле для пароля — это `hint`, `enabled false` и `type \password` в вашем дереве.

**Типизированный интерфейс генерируется из того же дерева.** `mol/string/-view.tree/string.view.tree.d.ts` перечисляет те же свойства сигнатурами TypeScript, а [справочник API](#!section=docs/page=api-mol-string) на этом сайте собран из этого файла. Все трое согласованы, потому что все трое сделаны из одного источника.

**У большинства компонентов есть папка `demo/` и `readme.md`.** `mol/string/demo/demo.view.tree` показывает поле с подсказкой, выключенное и с заранее заданным значением. Когда компонент нужен в каком-то состоянии, найдите ближайшее демо и скопируйте строку.

Вместе это укладывает placeholder примерно в минуту:

```bash
ls mol | grep string
cat mol/string/string.view.tree
```

Вы видите `hint \` под `$mol_string` и пишете `hint \Search` под своим `$mol_string`.

## Имена

Всё в `snake_case`: имена свойств в `view.tree`, имена методов в TypeScript, атрибуты, которые фреймворк вешает на DOM-узлы для стилизации. Под-вью начинаются с большой буквы (`Query`), значения — с маленькой (`query`).

Имя в дереве и имя метода в классе должны совпадать буква в букву. `exchange_form` в дереве и `exchangeForm` в классе — это два никак не связанных свойства: классовое никто не читает, древесное остаётся со значением по умолчанию, и никакой ошибки об этом не скажет. Когда переопределение будто бы ничего не делает, проверять надо первым делом это. [Решение проблем](#!section=docs/page=troubleshooting) перечисляет этот и остальные случаи, когда на экране не то, а компилятор молчит.
