# React, Vue ও Svelte থেকে

আপনি যদি React, Vue বা Svelte দিয়ে UI বানিয়ে থাকেন, $mol যা করে তার বেশিরভাগ আপনি ইতিমধ্যেই বোঝেন——শুধু নামগুলো আলাদা। এই ফ্রেমওয়ার্কগুলো যথার্থ কারণেই চমৎকার ও জনপ্রিয়; এই পৃষ্ঠা একটি অনুবাদ ছক, প্রতিযোগিতা নয়, যাতে আপনি দ্রুত স্বচ্ছন্দ বোধ করেন।

## ধারণার মানচিত্র

| ধারণা | React | Vue | Svelte | $mol |
|------|-------|-----|--------|------|
| কম্পোনেন্ট | ফাংশন / ক্লাস | SFC (`.vue`) | `.svelte` ফাইল | `.view.tree` + `.view.ts` |
| লোকাল স্টেট | `useState` | `ref` / `reactive` | `let x` | `@ $mol_mem` |
| উদ্ভূত মান | `useMemo` | `computed` | `$: y = …` | `@ $mol_mem` (অন্য সেল পড়ে) |
| সাইড ইফেক্ট | `useEffect` | `watchEffect` | `$: { … }` | `@ $mol_action` (সুস্পষ্ট, কখনো স্বয়ংক্রিয় নয়) |
| Props | props | props | `export let` | `view.tree`-এ বাইন্ডিং |
| ইভেন্ট | `onClick` | `@click` | `on:click` | `click? <=> handler?` |
| দ্বিমুখী ইনপুট | নিয়ন্ত্রিত ইনপুট | `v-model` | `bind:value` | `value? <=> field?` |
| তালিকা | `items.map()` | `v-for` | `{#each}` | কী-যুক্ত `Row*` |
| শর্ত | `cond && …` | `v-if` | `{#if}` | সরাতে `null` অ্যাসাইন করুন |
| শেয়ার্ড স্টেট | Redux / Context | Pinia / provide | স্টোর | `@ $mol_mem`-সহ যেকোনো অবজেক্ট |
| রাউটিং | React Router | Vue Router | SvelteKit | `$mol_state_arg` |
| স্টাইলিং | CSS-in-JS | স্কোপড `<style>` | `<style>` | টাইপড `.view.css.ts` |

## যা সাধারণত নতুন লাগে

- **রিয়্যাক্টিভিটি স্বয়ংক্রিয় এবং ঐচ্ছিক নয়।** Vue-র `ref` বা Svelte-র `$:`-এর মতো, একটি `@ $mol_mem` মান নিজেই তার পাঠকদের আপডেট করে——কিন্তু রক্ষণাবেক্ষণের মতো কোনো ডিপেন্ডেন্সি অ্যারে নেই, কোথাও কোনো ম্যানুয়াল সাবস্ক্রিপশনও নেই।
- **ইফেক্ট গণনা থেকে আলাদা।** React উদ্ভব ও ইফেক্টকে হুকে ভাঁজ করে; $mol সেগুলোকে পৃথক রাখে: `@ $mol_mem` শুধু গণনা করে, `@ $mol_action` ইফেক্ট চালায়। এই বিভাজনই "এটা দুবার চলল কেন?"-জাতীয় বেশিরভাগ ধাঁধা দূর করে।
- **স্টেট কেবলই অবজেক্ট।** গ্রহণ করার মতো কোনো নিবেদিত স্টোর লাইব্রেরি নেই——একটি শেয়ার্ড মান হলো যেকোনো অবজেক্টের ওপর একটি রিয়্যাক্টিভ প্রপার্টি, তাই গ্লোবাল স্টেট ও কম্পোনেন্ট স্টেট একইভাবে কাজ করে।

## তুমি সমাধান করো নাকি ফ্রেমওয়ার্ক সমাধান করে

গভীরতর পার্থক্যটা উপরের শব্দভাণ্ডারে নয় — বরং *কে* বারবার ফিরে আসা সমস্যাগুলো সমাধান করে তাতে। React, Vue বা Svelte-এ এগুলোর বেশিরভাগই এমন প্যাটার্ন যা তুমি প্রতিটি কম্পোনেন্টে আবার লেখো এবং নিজের মতো করে ভাঙো। $mol-এ এগুলো একটিমাত্র মেকানিজমের বৈশিষ্ট্য, তাই আরও সুন্দর API পাওয়ার বদলে গোটা এই শ্রেণির কাজই উধাও হয়ে যায়।

- **স্টেট স্টোর** — React-এর পাঁচটি স্টোরেজ সাবসিস্টেম (Redux + RTK Query + `useState` + `useReducer` + Context) একটিতে মিলিয়ে যায়: কম্পোনেন্টের রিঅ্যাকটিভ ফিল্ড।
- **রিঅ্যাকটিভিটি** — অন্যত্র উপরে বসানো (MobX, signals); এখানে ভিতে থাকে, তাই কোনো কিছুকেই opt-in করতে হয় না।
- **ক্র্যাশ আইসোলেশন** — হাতে বসানো `<ErrorBoundary>`-এর বিপরীতে প্রতিটি কম্পোনেন্ট ডিফল্টে নিজেই নিজের সীমানা।
- **ইফেক্ট** — এক ডজন পরিস্থিতিজুড়ে `useEffect`/`useMemo`/deps চেকলিস্টের বিপরীতে একটি মেথড, বা একটি action-সহ মেথড। গাছে একটাই শাখাবিন্দু, বারোটা নয়।
- **ভার্চুয়ালাইজেশন** — প্রতিটি তালিকায় একটি থার্ড-পার্টি কম্পোনেন্টের বিপরীতে ভিউপোর্টের বাইরের সবকিছু কেবল অস্তিত্বহীন।

উপরের টেবিল যেখানে জিনিসগুলোর নাম বদলায়, সেখানে $mol আসলে সেগুলোকে সরিয়ে দেয়।
