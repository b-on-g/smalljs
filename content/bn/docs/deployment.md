# ডিপ্লয়

বিল্ড করা $mol অ্যাপ মানে স্ট্যাটিক ফাইলের একটি ফোল্ডার। চালানোর মতো সার্ভার নেই, বাঁচিয়ে রাখার মতো Node প্রসেস নেই, বেছে নেওয়ার মতো অ্যাডাপ্টারও নেই: যা একটি ফোল্ডার হোস্ট করতে পারে, তা-ই অ্যাপটিও হোস্ট করে।

## আপনি আসলে কী ডিপ্লয় করেন

বিল্ড সবকিছু মডিউলের ভিতরের `-/` ফোল্ডারে লেখে:

```
my/hello/-/
├── index.html                 ডিপ্লয়ের পথ অনুযায়ী নতুন করে লেখা
├── web.js                     পুরো অ্যাপ, একটিই ফাইল
├── web.css
├── web.locale=en.json         প্রতিটি ভাষার জন্য একটি
├── manifest.json
└── …                          `deploy` নির্দেশ যা কিছু কপি করে এনেছে
```

ওই ফোল্ডারটিই সাইট। যেকোনো স্ট্যাটিক হোস্ট থেকে পরিবেশন করুন, অ্যাপ চলবে।

`my/hello/`-এর বাকি সবকিছু সোর্স, আর `-/` তৈরি হওয়া: ওয়ার্কস্পেসের `.gitignore` `-*` উপেক্ষা করে, তাই বিল্ডের ফল প্রকল্পের নিজের ইতিহাসে কখনও ঢোকে না। ওয়েবে সেটি যায় ডিপ্লয় ব্রাঞ্চ হয়ে।

## সংক্ষেপে

ওয়ার্কফ্লো লিখে দেয় স্ক্যাফোল্ডার, তাই নতুন প্রকল্প পুশেই প্রকাশ পায়:

```bash
npx create-view-tree-lsp my/hello
git push
```

`.github/workflows/deploy.yml` মডিউল বিল্ড করে `my/hello/-/` কে `gh-pages` ব্রাঞ্চে পুশ করে। **Settings → Pages → Source** যখন *Deploy from a branch* আর `gh-pages` নির্বাচিত, GitHub তখনই ওই ব্রাঞ্চ পরিবেশন করে — এবং যে রিপোজিটরিতে ওই ব্রাঞ্চ আছে, তার ডিফল্টও এটিই। ঠিকানা 404 দিলে সবার আগে এই সেটিংটাই দেখবেন।

এরপর সাইটটি থাকে `https://<user>.github.io/<repo>/`-এ।

## ওয়ার্কফ্লো আসলে কী করে

দুটি অ্যাকশনই পুরোটা টানে, আর প্রত্যেকটি নেয় গোটা দুই ইনপুট:

```yaml
- uses: hyoo-ru/mam_build@master2
  with:
      package: "my/hello"     # কোন ফোল্ডার বিল্ড হবে, ওয়ার্কস্পেস থেকে পথ
      modules: "app"          # তার ভিতরের কোন মডিউলগুলো

- uses: hyoo-ru/gh-deploy@v4.4.1
  if: github.ref == 'refs/heads/main'
  with:
      folder: "my/hello/app/-"
```

`mam_build` আপনার প্যাকেজের চারপাশে MAM ওয়ার্কস্পেস বিছিয়ে দেয়, কোডের `$name` টোকেনগুলোকে সেই রিপোজিটরিতে মেলায় যেখানে ওরা থাকে, তারপর বিল্ড করে। লকফাইলও লাগে না, `npm install` ধাপও না: নির্ভরতার তালিকা মানেই `.meta.tree`-এর রেজিস্ট্রি, যেমনটা [প্রকল্পের গঠন](#!section=docs/page=structure) বলে।

`gh-deploy` বিল্ড করা ফোল্ডারটিকে `gh-pages`-এ কমিট করে। `target-folder` সেটিকে রুটের বদলে সাবফোল্ডারে রাখে — ব্রাঞ্চ প্রিভিউ এভাবেই হয়:

```yaml
- name: Deploy feature branch
  if: startsWith(github.ref, 'refs/heads/feature/')
  uses: hyoo-ru/gh-deploy@v4.4.1
  with:
      folder: "my/hello/app/-"
      target-folder: ${{ github.ref_name }}
```

তখন প্রতিটি `feature/*` ব্রাঞ্চের একই Pages সাইটে নিজের ঠিকানা থাকে, আর ব্রাঞ্চ মুছে গেলে `delete` ট্রিগার ফোল্ডারটিও সরিয়ে দেয়।

## ডিপ্লয়ের জন্য দরকারি একটি ফাইল

যে প্যাকেজ ডিপ্লয় হয়, তার পাশে এক লাইনের `.gitattributes` লাগে:

```
* -text
```

ডিপ্লয় মানে বিল্ডের ফলকে একটি ব্রাঞ্চে কমিট করা, আর সেই ফলে কেবল টেক্সট থাকে না। ওই কমিটে যাওয়ার পথে নর্মালাইজ হয়ে যাওয়া ফন্ট আর ছবি পাঠকের কাছে ভাঙা অবস্থায় পৌঁছায়, অথচ বিল্ড নিজে সবুজই থাকে। ফাইলটি স্ক্যাফোল্ডার লিখে দেয়; নিজের হাতে বানানো রিপোজিটরিতে হাতে যোগ করুন।

## যে ফাইলগুলোর জায়গা সাইটের রুটে

`meta.tree`-এর `deploy \/path` ফাইলটিকে `-/`-এ কপি করে, **ওয়ার্কস্পেস-সাপেক্ষ পথ অক্ষত রেখে**। কোড যেসব অ্যাসেটকে ডাকে তাদের জন্য এটাই ঠিক, আর হোস্ট রুটে যেসব ফাইল খোঁজে তাদের জন্য নয়। `CNAME`, `robots.txt`, সার্চ কনসোলের মালিকানা যাচাইয়ের পাতা: এগুলো বিল্ডের পরে আর ডিপ্লয় ধাপের আগে ওয়ার্কফ্লোর একটি ধাপে কপি করুন।

```yaml
- name: Copy root-level files
  run: cp my/hello/public/CNAME my/hello/app/-/CNAME
```

## স্ট্যাটিক হোস্টে গভীর লিংক

পাথ রাউটিং ব্যবহার করা অ্যাপ (`#!section=docs` নয়, `/section=docs/page=views`) হোস্টের কাছে একটাই জিনিস চায়: মাউন্টের নিচে যেকোনো অচেনা পথকে অ্যাপের `index.html` ফেরত দিতে হবে। নইলে গভীর লিংকে প্রথম আঘাতই 404, আর কেবল হোম থেকে চলাচলই কাজ করে।

GitHub Pages-এ রিরাইট নিয়ম নেই, তাই পথটা যায় তার `404.html` দিয়ে: অচেনা যেকোনো পথে সেটিই পরিবেশিত হয়, আর ভিতরের কয়েক লাইন ঠিকানাটিকে `index.html`-এ ফিরিয়ে দেয়, যাকে রাউটার আসল রুটে খুলে নেয়। উপরের ফাইলগুলোর মতোই বিল্ডের ফলাফলের পাশে কপি করুন।

অন্য হোস্টরা এক লাইনেই বলে দেয়: nginx-এ `try_files $uri /index.html`, Caddy-তে `try_files {path} /index.html`, Netlify-তে `/* /index.html 200`।

হ্যাশ রাউটারে (ডিফল্ট) চলা অ্যাপের এসবের কিছুই লাগে না: `#`-এর পরের কিছুই সার্ভার পর্যন্ত পৌঁছায় না।

## পুশের আগে দেখে নিন

বিল্ড স্থানীয়ভাবে আর CI-তে একই, তাই নিজের মেশিনে সবুজ অডিট মানে সবুজ ডিপ্লয়:

```bash
npx mam my/hello/app
cat my/hello/app/-/web.audit.js
```

`Audit passed` — এটুকুই পুরো রিপোর্ট। আসল জিনিসটা দেখতে যেকোনো স্ট্যাটিক সার্ভার দিয়ে ফোল্ডারটি পরিবেশন করুন:

```bash
npx serve my/hello/app/-
```

## GitHub Pages ছাড়াও

উপরের কিছুই GitHub-নির্দিষ্ট নয়। আউটপুট একটি ফোল্ডার, ডিপ্লয় মানে একটি কপি। Netlify, Cloudflare Pages, CDN-এর পিছনে S3, VPS-এ nginx, ভিতরে ওই ফোল্ডার রাখা একটি ডকার ইমেজ — বিল্ড ধাপ সেই একই `npx mam my/hello/app`, আর আপনি আপলোড করেন `my/hello/app/-`।

অফলাইনে চলার মতো ইনস্টলের জন্য [অফলাইন](#!section=docs/page=offline) বান্ডল ক্যাশ করা সার্ভিস ওয়ার্কার যোগ করে, আর সেই একই ফোল্ডার ইনস্টলযোগ্য অ্যাপে পরিণত হয়।
