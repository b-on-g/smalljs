# ইনস্টলেশন

[শুরু করা](#!section=docs/page=getting-started) আপনাকে ধাপে ধাপে আপনার প্রথম অ্যাপের মধ্য দিয়ে নিয়ে যায়। এই পৃষ্ঠাটি রেফারেন্স: একটি $mol প্রকল্প কীভাবে সাজানো হয় এবং বিল্ড কীভাবে কাজ করে।

## প্রয়োজনীয়তা

- **Node.js 18+** এবং **git**। এ ছাড়া আর কিছুই গ্লোবালি ইনস্টল করা হয় না।

## MAM ওয়ার্কস্পেস

$mol অ্যাপগুলো **MAM**-এর ভেতরে থাকে — এটি বিল্ড টুল এবং মডিউল রেজিস্ট্রি। আপনি একবার ক্লোন করেন এবং এর ভেতরে আপনার মডিউল তৈরি করেন:

```bash
git clone https://github.com/hyoo-ru/mam.git ./mam
cd mam
npm install
npm start
```

`npm start` `http://localhost:9080/`-এ একটি ওয়াচিং ডেভেলপমেন্ট সার্ভার চালায়। এটি সেভ করার সময় পুনরায় বিল্ড করে এবং স্বয়ংক্রিয়ভাবে নির্ভরতা সমাধান করে — আপনি কখনও কোনো বান্ডলার কনফিগ রক্ষণাবেক্ষণ করেন না।

## মডিউল কীভাবে নামকরণ হয়

প্রতিটি কম্পোনেন্টের নাম একটি ফোল্ডার পাথের সাথে ম্যাপ করে, এবং **প্রতিটি আন্ডারস্কোর একটি ফোল্ডার বিভাজক**:

```
$my_app          →  my/app/
$my_app_header   →  my/app/header/
```

মডিউল ফোল্ডারের নামে কখনও আন্ডারস্কোর থাকে না — একাধিক শব্দের নামের জন্য নেস্টেড ফোল্ডার ব্যবহার করুন। আপনি যে কম্পোনেন্ট ব্যবহার করছেন সেটি যদি কখনও বান্ডলে না দেখা যায়, প্রায় সবসময়ই ফোল্ডার পাথ ক্লাসের নামের সাথে মেলে না।

## একটি মডিউলের গঠন

একটি কম্পোনেন্ট হলো এমন একটি ফোল্ডার যাতে চারটি পর্যন্ত ফাইল থাকতে পারে:

| ফাইল | উদ্দেশ্য |
|------|------|
| `name.view.tree` | ঘোষণামূলক লেআউট |
| `name.view.ts` | আচরণ (TypeScript) |
| `name.view.css.ts` | টাইপযুক্ত স্টাইল |
| `name.view.tree`, `index.html` | একটি অ্যাপ মডিউলের এন্ট্রি পয়েন্ট |

একটি অ্যাপের `index.html` রুট কম্পোনেন্ট মাউন্ট করে:

```html
<body mol_view_root>
	<div mol_view_root="$my_app"></div>
	<script src="web.js"></script>
</body>
```

## প্রোডাকশনের জন্য বিল্ড

ডেভেলপমেন্ট সার্ভার চলার সময়েই বিল্ড করে, তবে আপনি ওয়ার্কস্পেসের রুট থেকে যেকোনো মডিউল স্পষ্টভাবে বিল্ড করতে পারেন:

```bash
npm run start my/app
```

আউটপুট `my/app/-/`-এ যায় — যার মধ্যে রয়েছে `web.js`, `web.css` এবং `web.audit.js`। **সর্বদা অডিট পরীক্ষা করুন:** একটি পরিচ্ছন্ন `web.audit.js` মানে কোনো অব্যবহৃত নির্ভরতা নেই এবং কোনো টাইপ ত্রুটি নেই।

## npm প্যাকেজ যোগ করা

`require` দিয়ে একটি প্যাকেজ রেফারেন্স করুন এবং MAM পরবর্তী বিল্ডে সেটি ইনস্টল করবে এবং বান্ডেলে রাখবে:

```typescript
const dayjs = require( 'dayjs' ) as typeof import( 'dayjs' )
```

### রানটাইমে প্যাকেজ লোড করা

যে ভারী লাইব্রেরি শুধু একটি স্ক্রিনের দরকার, সেটিকে `web.js`-এ রাখতে হবে না। এর আগে থেকে বিল্ড করা ব্রাউজার ফাইলটি বান্ডেলের পাশে রাখুন এবং প্রথম ব্যবহারের সময় লোড করুন।

মডিউলের `meta.tree`-এ ফাইলটি লিখুন:

```tree
deploy \/node_modules/@turf/turf/turf.min.js
```

প্যাকেজ না থাকলে `deploy` সেটি ইনস্টল করে এবং ফাইলটি `-/node_modules/@turf/turf/turf.min.js`-এ কপি করে, ডেভ সার্ভারে এবং প্রোডাকশন বিল্ডে একইভাবে। `$mol_import.script` দিয়ে এটি লোড করুন:

```typescript
namespace $ {
	export class $my_app_turf extends $mol_object {

		@ $mol_mem
		static api() {
			$mol_import.script( './node_modules/@turf/turf/turf.min.js' )
			return ( globalThis as any ).turf as typeof import(
				'@turf/turf'
			)
		}

	}
}
```

- পাথটি আপেক্ষিক এবং `-/`-এর পেজের সাপেক্ষে নির্ধারিত হয়, তাই একই কোড ডেভ সার্ভারে, `test.html`-এ এবং সাবপাথের অধীনে ডিপ্লয়ে কাজ করে। শুরুর `/` কেবল তখনই কাজ করে যখন অ্যাপটি ডোমেনের রুটে থাকে।
- `$mol_import.script` স্ক্রিপ্ট লোড না হওয়া পর্যন্ত ফাইবার স্থগিত রাখে এবং URL অনুযায়ী ক্যাশ করে: ফাইলটি একবারই আনা হয়, আর `$mol_mem`-এর ভেতরে যা কিছু `$my_app_turf.api()` পড়ে, তা কেবল অপেক্ষা করে।
- গ্লোবাল নামটি, এখানে `turf`, লাইব্রেরির ব্রাউজার বিল্ড যা নির্ধারণ করে তাই। কোনটি, তা এর README-তে লেখা থাকে।
- `typeof import( … )` পূর্ণ টাইপিং দেয়। প্যাকেজের নাম আলাদা লাইনে রাখুন: বিল্ডার এক লাইনে লেখা `require( '…' )` এবং `import( '…' )`-কে নির্ভরতা হিসেবে ধরে এবং শেষ পর্যন্ত পুরো প্যাকেজটি `web.js`-এ রেখে দেবে।
