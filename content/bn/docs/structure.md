# প্রকল্পের কাঠামো

একটি $mol প্রকল্পের চারটি স্তর একটির ভিতরে আরেকটি: আপনার ক্লোন করা **ওয়ার্কস্পেস**, তার ভিতরের **প্যাকেজ**, প্যাকেজের ভিতরের **মডিউল**, আর মডিউলের ভিতরের **ফাইল**। এই বিন্যাস একটি বাস্তব প্রশ্নের উত্তর দেয় — নতুন প্রকল্প কোথায় যাবে আর তার ইতিহাস কার — এবং বিল্ড যা কিছু করে তার প্রায় সবই এখান থেকেই আসে।

```structure
mam/                         ওয়ার্কস্পেস — ক্লোন করা MAM
├── .meta.tree               রেজিস্ট্রি: কোন প্যাকেজ কোন রিপো থেকে
├── mol/                     প্যাকেজ — ফ্রেমওয়ার্ক নিজেই, নিজের git রিপো
└── my/                      প্যাকেজ — আপনার, আপনার নিজের git রিপো
    ├── .gitattributes       বিল্ড করা বাইনারি অক্ষত রাখে
    ├── my.meta.tree         আপনার নিজের প্রকল্পের রেজিস্ট্রি
    └── hello/               প্রকল্প — একটি মডিউল, আর নিজের git রিপো
        ├── index.html       এন্ট্রি পয়েন্ট (কেবল অ্যাপ মডিউলের)
        ├── hello.view.tree
        └── form/            সাবমডিউল — $my_hello_form
```

এই পাতায় তালিকার প্রতিটি লাইনের পাশে একটি প্রশ্নচিহ্ন আছে, যেটি বলে কেন সেটি সেখানে; নিচের অংশগুলো একই কথা বিশদে বলে।

## প্রকল্প শুরু করা

পাঁচ ধাপ। কেবল প্রথমটিই বারবার লাগে, আর শেষ তিনটি স্ক্যাফোল্ডার আপনার হয়ে করে দিতে পারে।

**১. ওয়ার্কস্পেসটি একবার ক্লোন করুন।** এরপর আপনি যা কিছু লিখবেন, সব এর ভিতরেই থাকবে।

```bash
git clone https://github.com/hyoo-ru/mam.git
cd mam
```

**২. নিজের একটি প্যাকেজ বানান।** একটি ছোট নামের ফোল্ডার — আপনার নাম, আপনার কোম্পানি, আপনার হ্যান্ডল — আর নিজের একটি git রিপো। আপনি যত প্রকল্প শুরু করবেন, সবের পাত্র এটিই:

```bash
mkdir my
cd my
git init
```

যেখানে কোড রাখেন সেখানেই তুলুন, পাবলিক হোক বা প্রাইভেট। সঙ্গে `* -text` একটিমাত্র লাইনের `.gitattributes` রেখে দিন; কারণটা নিচে প্যাকেজ অংশে আছে।

**৩. রেজিস্ট্রি যোগ করুন।** `my/my.meta.tree` হলো আপনার প্যাকেজের ভিতরের প্রকল্পগুলোর তালিকা। শুরুতে ফাঁকা, প্রতিটি প্রকল্পের জন্য একটি করে লাইন যোগ হয়:

```tree
pack hello git \https://github.com/you/hello.git
```

MAM এটি ঠিক সেভাবেই পড়ে যেভাবে এক ধাপ উপরের ওয়ার্কস্পেসের `.meta.tree` পড়ে, তাই যে সহকর্মী `my/` ক্লোন করবেন তিনি প্রকল্পগুলোও পাবেন।

**৪. প্রকল্পটি বানান, নিজের রিপোসহ।** ফোল্ডারই কম্পোনেন্ট — `my/hello/` মানে `$my_hello` — আর ইতিহাস তার নিজের, আপনার প্যাকেজের নয়, $mol-এরও নয়:

```bash
mkdir hello
cd hello
git init
```

এই আলাদা থাকাটাই বিন্যাসের মূল কথা: `my/hello/`-এর কমিট যায় `hello` রিপোতে, কখনও `my`-তে নয়, `mol`-এও নয়।

**৫. নিবন্ধন করুন।** ৩ নম্বর ধাপের `pack` লাইনটি `my/my.meta.tree`-তে যোগ করুন, তাহলে আপনার প্যাকেজের নতুন চেকআউট প্রকল্পটিকে নাম ধরে নিয়ে আসবে।

২ নম্বর ধাপের পরে যেকোনো সময় [স্ক্যাফোল্ডার](#!section=docs/page=tooling) আপনার হয়ে একটি চালু মডিউল লিখে দেবে:

```bash
npx create-view-tree-lsp my/hello
```

## ওয়ার্কস্পেস

MAM একবার ক্লোন করে তার ভেতরেই কাজ করবেন। এটি এমন কোনো ফোল্ডার নয় যেখানে নির্ভরতাগুলো কপি হয়ে আসে: প্রতিটি প্যাকেজ সেখানে নিজস্ব git চেকআউট হিসেবে, ইতিহাস সমেত বসে থাকে, ফলে আপনি ফ্রেমওয়ার্কের সোর্স পড়তে পারেন, তাতে একটা `debugger` বসাতে পারেন, এবং একই ওয়ার্কিং কপি থেকে পুল রিকোয়েস্ট খুলতে পারেন।

রুটের `.meta.tree` হলো সেই রেজিস্ট্রি যা এটিকে সম্ভব করে:

```tree
pack mol git \https://github.com/hyoo-ru/mam_mol.git
pack hyoo git \https://github.com/hyoo-ru/mam_hyoo.git
pack lib git \https://github.com/hyoo-ru/mam_lib.git
```

বিল্ড যখন `$mol_view` দেখে অথচ `mol/` ফোল্ডার তখনও নেই, তখন সে নামটি এখানে খুঁজে নিয়ে রিপোজিটরিটি ক্লোন করে। কিছুই ভেন্ডর করা হয় না এবং কিছুই সমতল করা হয় না।

## প্যাকেজ

শীর্ষ স্তরের একটি ফোল্ডারই একটি প্যাকেজ, আর একটি প্যাকেজ হলো একটি git রিপোজিটরি। আপনার নিজের প্যাকেজ কেবল একটি ফোল্ডার যার নাম আপনি দেন: যতক্ষণ সেটি স্থানীয় থাকে ততক্ষণ কোনো নিবন্ধন লাগে না, আর যেদিন নাম দিয়ে সেটি আনতে চাইবেন সেদিন একটি `pack` লাইন লাগে।

প্যাকেজ নেস্ট করে। একটি প্যাকেজ তার ভেতরের ফোল্ডারগুলোর জন্য নিজস্ব `pack` ঘোষণা বহন করতে পারে, আর MAM সেগুলো পড়ে সেই ফোল্ডারের `meta.tree` থেকে যেটি প্যাকেজটিকে ধারণ করবে। এই সাইটটি `bog/smalljs/`-এ থাকে এবং নিজেই একটি রিপোজিটরি, যা `bog/bog.meta.tree`-তে তালিকাভুক্ত; আর সেই ফাইলটি রুট `.meta.tree`-তে তালিকাভুক্ত `bog/` চেকআউটের ভেতরেই আছে।

### যে ফাইলটি প্রতিটি প্যাকেজের দরকার

যে প্যাকেজ ডিপ্লয় হয় তার একটিমাত্র লাইনের `.gitattributes` দরকার:

```
* -text
```

এটি git-এর লাইন-এন্ডিং নর্মালাইজেশন বন্ধ করে দেয়। এটি গুরুত্বপূর্ণ কারণ ডিপ্লয় মানে বিল্ড আউটপুট একটি ব্রাঞ্চে কমিট করা, আর সেই আউটপুট শুধু টেক্সট নয়: এই সাইট ৫৭টি বাইনারি ফাইল বয়ে নেয় — নিজে হোস্ট করা ফন্টগুলো, আর প্রতি পাতার একটি করে প্রিভিউ ছবি। ঢোকার পথে নর্মালাইজ হয়ে গেলে পাঠকের কাছে সেগুলো ভাঙা ছবি ও ফন্ট হয়ে পৌঁছায়, অথচ বিল্ড নিজে সবুজই থেকে যায়। MAM চেকআউটেরও রুটে একই ফাইল আছে, সেখানে ফন্ট ফরম্যাটগুলো বাড়তি করে `binary` চিহ্নিত।

স্ক্যাফোল্ডার এটি আপনার হয়ে লিখে দেয়; নিজে শুরু করা রিপোজিটরিতে হাতে যোগ করুন।

## মডিউল

মডিউল হলো একটি ফোল্ডার, আর ফোল্ডার হলো একটি কম্পোনেন্ট। কোনো import স্টেটমেন্ট নেই, কোনো মডিউল ম্যাপও নেই — ক্লাসের নাম *নিজেই* ঠিকানা, আর তার প্রতিটি আন্ডারস্কোর একটি ফোল্ডার বিভাজক:

```
$my_hello          →  my/hello/
$my_hello_form     →  my/hello/form/
$mol_button_major  →  mol/button/major/
$mol_after_frame   →  mol/after/frame/
```

রেজলিউশনের নিয়ম বলতে এটুকুই। বিল্ডার আপনার সোর্স টেক্সট স্ক্যান করে `$name` টোকেন খোঁজে, প্রতিটিকে `_` ধরে ভাঙে, আর ফোল্ডার ধরে হাঁটে। কোনো কিছুই নির্ভরতা ঘোষণা করে না; একটি নাম ব্যবহার করাই সেই ঘোষণা।

বাস্তব ফলাফল: **মডিউল ফোল্ডারের নামে কখনও আন্ডারস্কোর থাকে না।** `my/hello_form/` নামের একটি ফোল্ডার খোঁজা হবে `my/hello/form/`-এ এবং কখনও পাওয়া যাবে না — লক্ষণ হলো এমন একটি ক্লাস যা আপনার এডিটরে কম্পাইল হয় কিন্তু বান্ডলে অনুপস্থিত।

যে মডিউলের সাবমডিউল আছে সেটিও নিজে কম্পোনেন্ট হতে পারে, দুটি আকারের যেকোনো একটিতে। `$mol_button` সরাসরি `mol/button/`-এ থাকে, `major/` ও `minor/`-এর পাশে। `$mol_view` এক ধাপ গভীরে, `mol/view/view/`-এ থাকে, কারণ `mol/view/`-এ `component/`, `selection/` ও `tree2/`-ও আছে। MAM আগে দ্বিগুণ পাথ চেষ্টা করে, তারপর ছোটটিতে ফিরে আসে, তাই দুই বিন্যাসই রেজলভ হয়।

## একটি মডিউলের ফাইল

প্রতিটি ফাইলই ঐচ্ছিক। মডিউল বলতে তার ভেতরে যে ফাইলগুলো আছে সেগুলোই।

| ফাইল | উদ্দেশ্য |
|------|---------|
| `hello.view.tree` | ঘোষণামূলক লেআউট |
| `hello.view.ts` | আচরণ: জেনারেট করা বেস ক্লাসকে এক্সটেন্ড করা ক্লাস |
| `hello.view.css.ts` | টাইপযুক্ত স্টাইল। শেষের `.ts`-টি খেয়াল করুন: এটি `$mol_style_define` ডাকা TypeScript, স্টাইলশিট নয় |
| `hello.ts` | ভিউ ছাড়াই একটি মডিউল — মডেল, ইউটিলিটি, নিছক লজিক |
| `hello.test.ts` | টেস্ট, বিল্ডার চালায় |
| `hello.locale=ru.json` | অনুবাদ; `.locale=<lang>.json`-এ শেষ হওয়া যেকোনো ফাইল তুলে নেওয়া হয় |
| `hello.meta.tree` | বিল্ড ও ডিপ্লয় নির্দেশিকা |
| `index.html` | এন্ট্রি পয়েন্ট — কেবল অ্যাপ মডিউলেরই দরকার |

এক্সটেনশনের আগের একটি সাফিক্স ফাইলটিকে একটিমাত্র পরিবেশে সীমিত করে:

- `frame.web.ts` — শুধু ব্রাউজার বান্ডল, যেমন `mol/after/frame/frame.web.ts`
- `build.node.ts` — শুধু Node বান্ডল, যেমন MAM বিল্ডার নিজে
- `hello.test.ts` — শুধু টেস্ট বান্ডল

বিল্ডার প্রতিটি অ্যাপের জন্য একটি `web` ও একটি `node` বান্ডল বানায় এবং অন্যটির জন্য চিহ্নিত ফাইলগুলো বাদ দেয়, ফলে প্ল্যাটফর্ম-নির্দিষ্ট কোডকে রানটাইমে কখনও নিজেকে আগলাতে হয় না।

মডিউলের পাশে কাঁচা `.css` ফাইলও গ্রহণ করা হয় — টাইপযুক্ত স্টাইল যে অল্প কয়েকটি জিনিস প্রকাশ করতে পারে না, যেমন `@keyframes` ও `content:`, তার জন্য ফ্রেমওয়ার্ক সেগুলো ব্যবহার করে। বাকি সবকিছুর জায়গা `.view.css.ts`, যেখানে প্রপার্টির নাম যাচাই হয়।

## জেনারেট করা ফোল্ডার হাইফেন দিয়ে শুরু হয়

MAM একটি নামকে সোর্স ধরে কেবল তখনই, যখন সেটি অক্ষর বা অঙ্ক দিয়ে শুরু হয়। বাকি সব বিল্ডের কাছে অদৃশ্য, আর সেই কারণেই প্রতিটি জেনারেট করা ফোল্ডারের আগে `-` বসে: আউটপুট তার ইনপুটের ঠিক পাশেই বসতে পারে, অথচ ইনপুট হিসেবে আবার পঠিত হয় না। একই কারণে ওয়ার্কস্পেসের `.gitignore` `-*` উপেক্ষা করে।

**`-view.tree/`** যেকোনো `.view.tree` ফাইলের পাশে হাজির হয় এবং ট্রি যাতে কম্পাইল হয় তা ধরে রাখে:

```
my/hello/-view.tree/
├── hello.view.tree.js            জেনারেট করা বেস ক্লাস
├── hello.view.tree.d.ts          তার টাইপযুক্ত ইন্টারফেস
└── hello.view.tree.locale=en.json  নিষ্কাশিত @-স্ট্রিংগুলো
```

আপনার `hello.view.ts` ওখানকার ক্লাসটিকে এক্সটেন্ড করে। দুই ফাইলের সম্পর্ক বলতে এটুকুই — [TypeScript থেকে view.tree](#!section=docs/page=from-ts-to-view-tree) জেনারেট করা কোড লাইন ধরে ধরে দেখায়।

**`-css/`** একটি কাঁচা `.css` ফাইলের পাশে হাজির হয় এবং একটি জেনারেট করা `.ts` ধরে রাখে, যা স্টাইলশিটটিকে `$mol_style_attach` কলে মুড়ে দেয়, ফলে সেটি `<link>` লাগার বদলে বান্ডলের সঙ্গেই যায়।

**`-/`** হলো আপনি যে মডিউলটি বিল্ড করেছেন তার বিল্ড আউটপুট। একটি অ্যাপের ক্ষেত্রে এতে থাকে `web.js`, `web.css`, `web.audit.js`, `web.d.ts`, `web.deps.json`, প্রতি ভাষার জন্য একটি করে `web.locale=<lang>.json`, তাদের `node` প্রতিরূপ, পুনর্লিখিত `index.html`, এবং জেনারেট করা `package.json` ও `manifest.json`। আপনি এই ফোল্ডারটিই ডিপ্লয় করেন: `app/-` কোনো স্ট্যাটিক হোস্টে প্রকাশ করাই গোটা ডিপ্লয় ধাপ।

এগুলোর কোনোটিই হাতে সম্পাদনা করা হয় না। সোর্স বদলালেই বিল্ডার এগুলো আবার লিখে ফেলে, তাই সেখানে করা কোনো সম্পাদনা পরের সেভেই মিলিয়ে যায়, আর কেন গেল তা বলার মতো কোনো ত্রুটিও আসে না। `.view.tree`, `.css` বা সোর্স বদলান, তারপর আবার বিল্ড করুন।

## meta.tree আসলে কী করে

`meta.tree` কোনো প্যাকেজ ম্যানিফেস্ট নয় এবং নির্ভরতার তালিকাও দেয় না — সেগুলো আসে কোড থেকে, যেখানে একটি `$mol_view` টোকেনই গোটা ঘোষণা। এটি বহন করে সেই মুষ্টিমেয় জিনিসগুলো যা কোড নিজে বলতে পারে না। এই সাইটের `app/app.meta.tree` পুরো ফাইলটাই এই:

```tree
include \/mol/offline/install
include \/bog/builderui/theme.css
deploy \/bog/smalljs/assets
```

- **`deploy \/path`** একটি ফাইল বা ফোল্ডার `-/`-এর ভেতরে কপি করে, ওয়ার্কস্পেস-সাপেক্ষ পাথ অক্ষুণ্ণ রেখে: `\/bog/smalljs/assets` গিয়ে বসে `app/-/bog/smalljs/assets/`-এ। যে স্ট্যাটিক ফাইলগুলো ডিপ্লয়কে বয়ে নিতে হয় অথচ কোনো কোড ইমপোর্ট করে না, তাদের জন্য: ছবি, ফন্ট, আইকন।
- **`include \/path`** ও **`require \/path`** এমন একটি মডিউল জোর করে টেনে আনে যাকে কিছুই রেফারেন্স করে না, যেমন `\/mol/offline/install`, যার গোটা উদ্দেশ্যই হলো লোডের সময় নিবন্ধিত হওয়া service worker। এদের পার্থক্য কেবল ক্রমে: `require` মডিউলটিকে বসায় যে কোড তাকে টেনেছে তার আগে, আর `include` তার পরে।
- **`pack <name> git \<url>`** হলো উপরে বর্ণিত রেজিস্ট্রি এন্ট্রি, যা পড়া হয় সেই ফোল্ডারের meta ফাইল থেকে যেটি প্যাকেজটিকে ধারণ করবে।

MAM একটি ফোল্ডারের প্রতিটি `*.meta.tree` ফাইল পড়ে, কাজেই নামটি প্রথা ছাড়া আর কোনো অর্থ বহন করে না: মডিউলের পাশে `<module>.meta.tree`, আর ওয়ার্কস্পেসের রুটে `.meta.tree`।

বাস্তবে `deploy`, `include` ও `require` অ্যাপ মডিউলেরই জিনিস, কারণ বিল্ড ও ডিপ্লয় তো সেটিই হচ্ছে; সাধারণ কম্পোনেন্ট সবকিছু নিজের কোড থেকেই রেজলভ করে, তাদের কোনো meta ফাইল লাগেই না। লাইব্রেরি মডিউল সেটি পায় কেবল তখনই, যখন সত্যিই তার একটি রেফারেন্সবিহীন নির্ভরতা থাকে — `mol/assert/assert.meta.tree` হলো `include \/mol/dev/format` একটিমাত্র লাইন, আর এটিই সাধারণ মাপ।

নির্দেশিকা নিয়ে আরও জানতে দেখুন [মডিউল মেটাডেটা](#!section=docs/page=meta)।
