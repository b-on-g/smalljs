# টুলিং

$mol যেকোনো এডিটরে কাজ করে, তবে একটি ছোট টুলসেট `.view.tree` এবং টাইপ করা স্টাইলকে অনেক বেশি আরামদায়ক করে তোলে: একটি প্রজেক্ট স্ক্যাফোল্ডার, একটি ল্যাঙ্গুয়েজ সার্ভার, Zed ও VS Code-এর জন্য এডিটর ইন্টিগ্রেশন, এবং একটি স্কিল যা LLM সহকারীদের এই ফ্রেমওয়ার্ক শেখায়।

## একটি প্রজেক্ট স্ক্যাফোল্ড করা

`create-view-tree-lsp` একটি রেডি-টু-রান $mol মডিউল তৈরি করে, যাতে আপনাকে বয়লারপ্লেট হাতে জোড়া লাগাতে না হয়:

```bash
npx create-view-tree-lsp bog/myapp
```

নিজের MAM কপির রুট থেকে চালান: মডিউল পাথ ওখান থেকেই হিসাব হয়, প্রকল্পেরও ঠিকানা ওটাই। ওয়ার্কস্পেসের বাইরে হলে কমান্ড সতর্ক করে, প্রথম বিল্ডে গিয়ে টের পাওয়ার বদলে।

আর্গুমেন্টটি হলো মডিউল পাথ (`namespace/name`, অথবা সমতুল্য `bog_myapp`)। এটি একটি কার্যকর অ্যাপের জন্য `view.tree`, `view.ts`, `view.css.ts` এবং `index.html` লেখে, সেই সঙ্গে এটি ডিপ্লয় করার GitHub Actions।

জেনারেটর যা যা যোগ করতে জানে, সবই ডিফল্টে থাকে। আপনি শুধু সেটুকুর নাম বলেন যা চান না:

```bash
npx create-view-tree-lsp bog/myapp --no-tauri --no-backend
```

- `--no-baza` — একটি local-first স্টোর **Giper Baza**
- `--no-docker` — `docker-compose.yml` ও nginx কনফিগসহ **Docker** সেটআপ
- `--no-tauri` — একটি **Tauri** ডেস্কটপ শেল
- `--no-backend` — `node:sqlite` স্টোরেজ এবং শেয়ার করা TypeScript আইটেম টাইপসহ `$mol_server` REST ব্যাকএন্ড
- `--no-prerender`, `--no-seo` — সার্চ-ইঞ্জিন দৃশ্যমানতা, যা নিচে [ধারাবাহিক ইন্টিগ্রেশন](#!section=docs/page=tooling/Docs.Body=%E0%A6%A7%E0%A6%BE%E0%A6%B0%E0%A6%BE%E0%A6%AC%E0%A6%BE%E0%A6%B9%E0%A6%BF%E0%A6%95%20%E0%A6%87%E0%A6%A8%E0%A7%8D%E0%A6%9F%E0%A6%BF%E0%A6%97%E0%A7%8D%E0%A6%B0%E0%A7%87%E0%A6%B6%E0%A6%A8)-এ বর্ণিত

অচেনা ফ্ল্যাগ পেলে চলাটাই থেমে যায়, যাতে টাইপো চুপচাপ কিছু রেখে না দেয়।

স্ক্যাফোল্ডারটি ল্যাঙ্গুয়েজ সার্ভারের CLI-এর ওপর একটি পাতলা র‍্যাপার, তাই `npx view-tree-lsp create bog/myapp` সরাসরি একই কাজ করে।

## অনুবাদ

অনুবাদ থাকে নিজের মডিউলের পাশেই, `<module>/<name>.locale=<lang>.json`-এ। কোডের জন্য এটি সুবিধাজনক, অনুবাদকের জন্য নয়: বাক্যের একটি তালিকার বদলে তাঁর হাতে আসে ত্রিশটি ছোট ফাইল।

**[$yuf_localizer](https://zerkalica.github.io/yuf/#!demo=yuf_localizer_demo)** ঠিক এই ফাঁকটাই ভরাট করে। প্রকল্পের ঠিকানা আর ভাষার কোড দিন, আর সে সব কী একটিমাত্র খোঁজযোগ্য তালিকায় দেখাবে — সঙ্গে চিহ্ন দেবে কোনগুলো এখনও বাকি: যেগুলো কেবল ইংরেজিতেই আছে, যেগুলো বদলেছেন কিন্তু সেভ করেননি, আর পুরোনো হয়ে যাওয়া যেগুলো প্রকল্পে আর নেই। অনুবাদ ব্রাউজারেই জমা থাকে যতক্ষণ না আপনি রপ্তানি করছেন, তাই দুই দফা কাজের মাঝে কিছু হারায় না।

অনুবাদকের কাজ শেষ হলে ফলাফল রপ্তানি করে আবার মডিউল অনুযায়ী ভাগ করে নিন:

```bash
# MAM-এর রুট থেকে
npx view-tree-lsp locale bog/myapp/app/- --exclude=mol --update
```

আর্গুমেন্ট হিসেবে ফোল্ডার বা একটিমাত্র লোকেল ফাইল, দুটোই চলে। ফ্ল্যাগ:

- `--include=` পথের একটি অংশ নেয় এবং কেবল সেই মডিউলগুলোই রাখে যাদের পথে সেটি আছে; যত খুশি বার দেওয়া যায়
- `--exclude=` উল্টোটা করে, সেগুলো বাদ দেয় — `--exclude=mol` দিলে ফ্রেমওয়ার্কের নিজের প্যাকেজে হাত পড়ে না
- `--update` বিদ্যমান ফাইলের সঙ্গে মেলায়: উৎসের মান জেতে, আর উৎসে না থাকা কী-গুলো থেকে যায়
- `--dry` পরিকল্পনা দেখায়, কিছুই লেখে না

প্রতিটি কী নিজের মডিউলের পথ বহন করে, তাই `$my_page_greeting` গিয়ে বসে `my/page/page.locale=ru.json`-এ — ঠিক যে সোর্সের সঙ্গে তার সম্পর্ক, তার পাশেই। তবে সেই মডিউল বের করা দেখতে যতটা সহজ, তত নয়: `_` ফোল্ডার আর শব্দ — দুটোই আলাদা করে, তাই "সবচেয়ে লম্বা মিলে যাওয়া পথ" ভুল উত্তর। `$my_page_lang_hint`-এ প্রপার্টির নাম শুরু হয় `lang` দিয়ে, আর পাশে সত্যিই `my/page/lang` সাবমডিউল থাকলে সে-ই কী-টি গিলে ফেলবে। তাই কমান্ডটি প্রতিটি সম্ভাব্য মডিউলকে জিজ্ঞাসা করে সে কোন কী ঘোষণা করেছে — MAM ঠিক সেগুলোই ওই মডিউলের `-view.tree` লোকেল ফাইলে লেখে — এবং কী-টি তার প্রকৃত মালিককে দেয়।

## ধারাবাহিক ইন্টিগ্রেশন

স্ক্যাফোল্ডার GitHub Actions-কে `.github/workflows/`-এ লেখে, তাই একটি নতুন প্রজেক্ট বাড়তি সেটআপ ছাড়াই ডিপ্লয় ও রিলিজ হয়।

`deploy.yml` প্রতিটি push-এ চলে। এটি `hyoo-ru/mam_build` দিয়ে অ্যাপ বিল্ড করে, `main` থেকে `app/-` **GitHub Pages**-এ প্রকাশ করে, এবং প্রতিটি `feature/*` ব্রাঞ্চকে নিজস্ব প্রিভিউ ফোল্ডার দেয় — ব্রাঞ্চ মুছে ফেলা হলে যা স্বয়ংক্রিয়ভাবে সরে যায়।

### SEO

দুটোই ডিফল্টে চালু এবং দুটোই `v*` ট্যাগে চলে:

- **`--no-prerender`** সেই ধাপটি সরায় যা আপনার তালিকাভুক্ত স্ক্রিনগুলো (যেমন `home`) `b-on-g/mol-prerender-action` দিয়ে স্ট্যাটিক HTML-এ রেন্ডার করে — এর জন্যই ক্রলার আর লিংক প্রিভিউ আসল কনটেন্ট দেখে।
- **`--no-seo`** `$bog_seo` রানটাইম সরায়: সাইটম্যাপসহ pathname রাউটার, `robots.txt`, `llms.txt` এবং প্রতি পাতায় মেটা ইনজেকশন। কাজটি বিল্ড সার্ভ করে, ক্যানোনিকাল প্রি-রেন্ডার করা HTML ডাম্প করে এবং তা আবার ডিপ্লয়ে ভাঁজ করে দেয়।

দুটো একই জমি ঢাকে আর একই ফোল্ডারে লেখে, তাই `deploy.yml`-এ একটাই যায়: যতক্ষণ চালু ততক্ষণ `$bog_seo`, আর `--no-seo` দিলেই prerender-action। সাইটম্যাপ ও প্রতি পাতার মেটাডেটা দরকার হলে `$bog_seo` রাখুন, আর গোটা কাজ যদি মুঠোখানেক পাবলিক স্ক্রিন হয় তবে prerender-action-এ নেমে আসুন।

### Tauri ডেস্কটপ

Tauri অপশন সহ, `tauri.yml` পুনর্ব্যবহারযোগ্য ওয়ার্কফ্লো `b-on-g/tauri-mol-workflow-template`-এর মাধ্যমে `v*` ট্যাগে (বা চাহিদামতো) ডেস্কটপ বাইনারি বিল্ড করে, ঠিক সেই মডিউল থেকে যা আপনি ওয়েবে ডিপ্লয় করেন।

## ল্যাঙ্গুয়েজ সার্ভার

`view-tree-lsp` হলো `view.tree` ফরম্যাটের জন্য একটি Language Server Protocol বাস্তবায়ন। এটি npx দিয়ে চাহিদামতো চালান, কোনো গ্লোবাল ইনস্টল দরকার নেই:

```bash
npx view-tree-lsp@latest
```

এটি আপনার ওয়ার্কস্পেস স্ক্যান করে এবং LSP-সক্ষম যেকোনো এডিটরকে দেয়:

- `$mol_*` কম্পোনেন্ট এবং আপনার নিজের প্রজেক্টে সংজ্ঞায়িত কম্পোনেন্ট ও প্রপার্টির জন্য কমপ্লিশন
- কার্সারের নিচের কম্পোনেন্টের মধ্যে সীমাবদ্ধ প্রপার্টি পরামর্শ
- নেভিগেশনের জন্য কম্পোনেন্ট ঘোষণার একটি আউটলাইন
- ফাইল বদলানোর সঙ্গে সঙ্গে লাইভ আপডেট

যেহেতু এটি LSP বলে, আপনি যেকোনো এডিটরের ল্যাঙ্গুয়েজ-ক্লায়েন্টকে `npx view-tree-lsp`-এ নির্দেশ করতে পারেন। নিচের দুটি ইন্টিগ্রেশন এটি আপনার জন্য জুড়ে দেয়।

## Zed

**View Tree Syntax Highlighting for $mol** এক্সটেনশনটি tree-sitter গ্রামার, ল্যাঙ্গুয়েজ সার্ভার এবং একটি ঐচ্ছিক আইকন থিম একসাথে বান্ডল করে। Zed-এর এক্সটেনশন ম্যানেজার থেকে এটি ইনস্টল করুন:

1. কমান্ড প্যালেট খুলুন (`Cmd+Shift+P` / `Ctrl+Shift+P`)
2. **zed: extensions** চালান
3. `view.tree` বা `mol` সার্চ করে এক্সটেনশনটি ইনস্টল করুন

আপনি `.view.tree` ফাইলের জন্য সিনট্যাক্স হাইলাইটিং, কমপ্লিশন এবং আউটলাইন পান। [সোর্স](https://github.com/Dev-cmyser/zed-view.tree-mol-support) এবং একটি মানানসই [আইকন থিম](https://github.com/Dev-cmyser/zed-viewtree-icon-theme) GitHub-এ আছে।

## VS Code

MAM ওয়ার্কস্পেস ইতিমধ্যে নিজের VS Code সেটআপ বহন করে। আপনি ক্লোন করা `mam` ফোল্ডার খুললে, VS Code `.vscode/extensions.json` থেকে প্রস্তাবিত এক্সটেনশন ইনস্টল করার প্রস্তাব দেয়:

- `nin-jin.vscode-language-tree` — `view.tree` ল্যাঙ্গুয়েজ সমর্থন
- `stan-donarise.view-tree-language` — সিনট্যাক্স ও গ্রামার
- `editorconfig.editorconfig` — সামঞ্জস্যপূর্ণ ফরম্যাটিং

একই ফোল্ডার `mol.code-snippets` সরবরাহ করে, তাই কম্পোনেন্ট ও বাইন্ডিং স্নিপেট কোনো বাড়তি সেটআপ ছাড়াই পাওয়া যায়। প্রম্পট গ্রহণ করুন, আর `.view.tree` ও TypeScript ফাইল শুরু থেকেই হাইলাইট হয়।

## LLM স্কিল

`mol_skill` একটি AI সহকারীকে $mol লেখার জন্য দরকারি প্রেক্ষাপট দেয়: `view.tree` সিনট্যাক্স, MAM মডিউলের গঠন, `view.ts` ও `view.css.ts`-এর ভাগাভাগি, Giper Baza দিয়ে ডেটা মডেলিং, এবং Tauri দিয়ে প্যাকেজিং। এটি সাধারণ একটি স্কিল ফোল্ডার, একটি `SKILL.md` ওয়ার্কফ্লো ও কয়েকটি রেফারেন্স গাইড, তাই skills ফরম্যাট পড়তে পারে এমন যেকোনো LLM টুল এটি লোড করতে পারে, Claude Code ও Cursor সহ। skills CLI দিয়ে ইনস্টল করুন:

```bash
npx skills add b-on-g/mol_skill --all -g
```
