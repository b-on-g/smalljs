# স্টেট ও রিয়্যাক্টিভিটি

$mol-এর স্টেট স্প্রেডশিটের মতো আচরণ করে: আপনি ঘোষণা করেন একটি মান কীভাবে গণনা হবে, আর তার ওপর নির্ভরশীল সবকিছু নিজে থেকেই আপডেট হয়। কোনো স্টোর নেই, ডিসপ্যাচ নেই, ইফেক্ট হুক নেই——ডিপেন্ডেন্সি গ্রাফ কী পুনরায় গণনা করতে হবে তা ট্র্যাক করে।

## রিয়্যাক্টিভ প্রপার্টি

`@ $mol_mem` দিয়ে ডেকোরেট করা একটি মেথড হলো একটি ক্যাশড, রিয়্যাক্টিভ সেল। এটি একবার চলে, ফলাফল মনে রাখে, এবং শুধু তখনই পুনরায় গণনা করে যখন এটি যা পড়েছিল তার কিছু পরিবর্তিত হয়।

```typescript
namespace $.$$ {
	export class $my_counter extends $.$my_counter {
		@ $mol_mem count() { return 0 }

		@ $mol_mem doubled() {
			return this.count() * 2
		}
	}
}
```

`doubled` `count` পড়ে, তাই এটি স্বয়ংক্রিয়ভাবে `count`-এ সাবস্ক্রাইব করে। `count` পরিবর্তন করুন, আর `doubled` দেখানো প্রতিটি ভিউ রিফ্রেশ হয়——হাতে কিছু সাবস্ক্রাইব করার নেই।

## পড়া ও লেখা

একটি প্রপার্টি একই সঙ্গে গেটার ও সেটার: পড়ার জন্য আর্গুমেন্ট ছাড়া কল করুন, লেখার জন্য একটি আর্গুমেন্ট সহ।

```typescript
@ $mol_action
increment() {
	this.count( this.count() + 1 )
}
```

## অ্যাকশন বনাম গণনা

এই একটি পার্থক্যই রিয়্যাক্টিভ কোডকে অনুমেয় রাখে:

- `@ $mol_mem` হলো একটি **বিশুদ্ধ গণনা**——শুধু অন্য সেল পড়ে এবং একটি মান রিটার্ন করে।
- `@ $mol_action` হলো একটি **ইফেক্ট**——স্টেটে লেখা, নেটওয়ার্ক কল ও টাইমার এখানে থাকে।

`@ $mol_mem`-এর ভেতর থেকে একটি সেলে লিখলে একটি ফিডব্যাক লুপ তৈরি হয় (লেখা একটি ডিপেন্ডেন্সি অকার্যকর করে, যা পুনরায় গণনা হয়, যা আবার লেখে)। $mol একে *সার্কুলার সাবস্ক্রিপশন* হিসেবে রিপোর্ট করে। সমাধান সবসময় একই: সাইড ইফেক্ট অ্যাকশনে রাখুন, গণনা বিশুদ্ধ রাখুন।

| `@ $mol_mem`-এ আপনি পারেন | কিন্তু পারেন না |
|---|---|
| অন্য সেল পড়তে | অন্য সেলে লিখতে |
| `new SomeClass()` | `fetch()`, `await` |
| একটি মান রিটার্ন করতে | `setTimeout`, DOM-এ লেখা |

বোতামের হ্যান্ডলার বেস ক্লাসে `@ $mol_mem` হিসেবে জেনারেট হয়; নিরাপদে লেখার জন্য সেগুলোকে `@ $mol_action` দিয়ে ওভাররাইড করুন:

```typescript
@ $mol_action
submit() {
	this.saved( true )
}
```

## উদ্ভূত স্টেট কম্পোজ হয়

যেহেতু ডিপেন্ডেন্সি স্বয়ংক্রিয়ভাবে ট্র্যাক হয়, উদ্ভূত মানগুলো কোনো তারের সংযোগ ছাড়াই চেইন হয়। প্রতিটি আগেরটি পড়ে; মূলে একটি পরিবর্তন ঠিক যতটুকু প্রয়োজন ততটুকুই ছড়িয়ে পড়ে:

```typescript
@ $mol_mem full_name() {
	return `${ this.first() } ${ this.last() }`.trim()
}

@ $mol_mem greeting() {
	return this.full_name() ? `Hello, ${ this.full_name() }!` : 'Hello!'
}
```

## কী-যুক্ত স্টেট

`@ $mol_mem_key` হলো একটি কী দিয়ে প্যারামিটারাইজড গণনা——প্রতি কী-তে একটি ক্যাশড সেল। প্রতি সারির মানের জন্য আদর্শ:

```typescript
@ $mol_mem_key
task_done( id: string, next?: boolean ) {
	const task = this.task( id )
	if ( next !== undefined ) task.Done( null )!.val( next )
	return task.Done()?.val() ?? false
}
```

## অ্যাসিঙ্ক শুধুই একটি মান

একটি `@ $mol_mem` থেকে একটি promise রিটার্ন করুন, আর এটি রিজলভ না হওয়া পর্যন্ত ভিউ একটি লোডিং স্টেট দেখায়——কোনো সুস্পষ্ট লোডিং ফ্ল্যাগ নেই:

```typescript
@ $mol_mem
async data() {
	const res = await fetch( '/api/data' )
	return await res.json()
}
```

[ডেটা ফেচিং](#!section=docs/page=data) এই প্যাটার্নের ওপর গড়ে ওঠে।

## ইভেন্টের মধ্যে ক্ষণস্থায়ী স্টেট

`view.tree`-এ ঘোষিত স্টেট আলাদা আলাদা ইভেন্ট হ্যান্ডলারের মধ্যে রিসেট হয় (ড্র্যাগ/প্যান/জেসচার সিকোয়েন্স), কারণ $mol প্রতিটি হ্যান্ডলারকে তার নিজস্ব ফাইবারে মুড়ে দেয়। যেসব মান এক ইভেন্ট থেকে পরের ইভেন্ট পর্যন্ত টিকে থাকা দরকার, তাদের জন্য রিয়্যাক্টিভ প্রপার্টির বদলে একটি সাধারণ TypeScript ফিল্ড ব্যবহার করুন:

```typescript
export class $my_canvas extends $.$my_canvas {
	// plain field — survives across events, not reactive
	drag_id = ''

	@ $mol_action pan_start() { this.drag_id = 'node_42' }
	@ $mol_action pan_move() { if ( this.drag_id ) { /* ... */ } }
}
```

ভিউকে যখন মানের প্রতি প্রতিক্রিয়া জানাতে হবে তখন একটি রিয়্যাক্টিভ সেল ব্যবহার করুন; শুধু হ্যান্ডলাররা যে ক্ষণস্থায়ী স্টেট পড়ে তার জন্য একটি সাধারণ ফিল্ড ব্যবহার করুন।
