# টেস্টিং

$mol ভিউ তার নিজের স্টেটের একটি ফাংশন, আর সেটিই বদলে দেয় টেস্ট দেখতে কেমন হবে। ব্যবহারকারীর একটি পরিস্থিতি লেখা হয় ভিউয়েরই মেথড কল হিসেবে: খসড়াটি বসান, অ্যাকশনটি চালান, ব্যবহারকারী যা দেখত তা পড়ুন।

```typescript
app.draft( 'Milk' )
app.add()
$mol_assert_equal( app.item_title( 0 ), 'Milk' )
```

কোনো সিলেক্টর নেই, ব্রাউজার নেই, Playwright বা Cypress নেই, কিছুর জন্য অপেক্ষা নেই। একই ফাইল আপনাকে এগুলোও দেয়:

- **গতি।** টেস্ট Node-এ মিলিসেকেন্ডে চলে; হাজারখানেক টেস্টে মিনিটখানেক লাগে। `node my/hello/-/node.test.js` একটি মডিউলের টেস্টগুলো চালায়।
- **শূন্য সেটআপ।** কম্পোনেন্টের পাশে রাখা `hello.test.ts` বিল্ডার তুলে নেয় আর `-/node.test.js`-এ কম্পাইল করে। `mam_build` দিয়ে ধারাবাহিক ইন্টিগ্রেশন সেটি চালায় এবং কোনো টেস্ট ব্যর্থ হলে বিল্ড ফেল করে।
- **কনটেক্সটের মাধ্যমে সার্ভিস বদল।** প্রতিটি টেস্ট নিজের `$` পায়, আর কম্পোনেন্ট `this.$.X` দিয়ে যা কিছুতে পৌঁছায়, সেই `$`-এ একটি টেস্ট-বদল বসিয়ে তা পাল্টে দেওয়া যায়। `$mol_fetch`-এর বদলে `this.$.$mol_fetch` লেখার কারণ এটাই: প্রথমটি বদলানো যায়, দ্বিতীয়টি যায় না।
- **মক করা সময়।** কনটেক্সটের মাধ্যমে বানানো টাইমার নিজে থেকে টিক করে না; `$mol_after_mock_warp()` সারিতে যা আছে তা চালিয়ে দেয়।
- **দরকার হলে আসল DOM।** Node বান্ডল jsdom বহন করে, তাই একই টেস্ট ফাইলে `dom_node()` আর `querySelectorAll` কাজ করে।

## ভিউয়ের মেথড দিয়ে একটি পরিস্থিতি

[কুকবুক](#!section=docs/page=cookbook) থেকে টুডু লিস্টটি ধরুন: একটি `draft?` স্ট্রিং, একটি `items` লিস্ট, একটি `add` অ্যাকশন আর একটি `delete` অ্যাকশন। এর টেস্ট থাকে `my/todo/todo.test.ts`-এ:

```typescript
namespace $ {
	$mol_test({

		'add an item and delete it'( $ ) {
			const app = $my_todo.make({ $ })

			app.draft( 'Milk' )
			app.add()
			$mol_assert_equal( app.items().length, 1 )
			$mol_assert_equal( app.item_title( 0 ), 'Milk' )
			$mol_assert_equal( app.draft(), '' )

			app.delete( 0 )
			$mol_assert_like( app.item_rows(), [] )
		},

		'blank draft adds nothing'( $ ) {
			const app = $my_todo.make({ $ })

			app.draft( '   ' )
			app.add()
			$mol_assert_like( app.items(), [] )
		},

	})
}
```

কয়েকটি জিনিস খেয়াল করার মতো:

- টেস্ট ফাইলটি `namespace $` ব্যবহার করে, `$.$$` নয়। কনটেক্সট `$` আর্গুমেন্ট হিসেবে আসে, প্রতিটি টেস্টের জন্য টাটকা, আর কম্পোনেন্টটি `Klass.make({ $ })` দিয়ে বানানো হয় যাতে সে ওই কনটেক্সট থেকেই সার্ভিস পড়ে।
- ক্লিক মানে হ্যান্ডলারের একটি কল। বাটন যা করে `app.add()` তা-ই; বাইন্ডিংটিও ঢোকাতে চাইলে `app.Add().click( event )` একই পথেই যায়।
- ব্যবহারকারী যা দেখে তা যাচাই করুন: `items()`, `item_rows()`, `sub()`, কোনো সাব-ভিউয়ের `title()`। স্ক্রিনের মধ্য দিয়ে যাচাই করা মডেল ক্লাস থেকে খসে পড়া ওভাররাইডটিও ধরে ফেলে, যা শুধু মডেলের টেস্ট ধরত না।
- `$mol_assert_equal` অভিন্নতা দিয়ে মেলায়, `$mol_assert_like` গঠন মেলায়, আর `$mol_assert_fail( ()=> ..., 'message' )` একটি থ্রো প্রত্যাশা করে।
- টেস্টের নামটিই তার বর্ণনা। বডিতে কোনো কমেন্ট থাকে না।

## একটি সার্ভিস মক করা

প্রতিটি টেস্ট গ্লোবাল কনটেক্সট থেকে উদ্ভূত একটি টাটকা কনটেক্সট পায়। কম্পোনেন্ট বানানোর আগে ওই `$`-এর কোনো সার্ভিসে একটি সাবক্লাস বসিয়ে দিন, তাহলে কম্পোনেন্টের ভেতরের প্রতিটি `this.$.X` ওই বদলিটিতেই গিয়ে ঠেকে। [ডেটা ফেচিং](#!section=docs/page=data)-এর `$my_users` কম্পোনেন্টের জন্য fetch-বদলিটি এই:

```typescript
namespace $ {
	$mol_test({

		'user names come from the response'( $ ) {
			$.$mol_fetch = class extends $.$mol_fetch {
				static override json( input: RequestInfo ) {
					if( String( input ).endsWith( '/users' ) ) return [ { id: 1, name: 'Ada' } ]
					return $mol_fail( new Error( 'Unexpected request: ' + input ) )
				}
			}
			const app = $my_users.make({ $ })
			$mol_assert_like( app.user_names(), [ 'Ada' ] )
		},

	})
}
```

কম্পোনেন্টের `users()` ডাকে `this.$.$mol_fetch.json( ... )`, তাই রিকোয়েস্টটি মকের কাছে যায় আর মানটি সিঙ্ক্রোনাসভাবেই পাওয়া যায়, কোনো অপেক্ষা ছাড়াই। কম্পোনেন্টটি যদি গ্লোবালের `$mol_fetch.json( ... )` ডাকত, মকের কাছে কিছু জিজ্ঞেস করাই হতো না। বিল্ট-ইন মকগুলো আগে থেকেই কনটেক্সটের গ্লোবাল `fetch` ও `XMLHttpRequest`-কে থ্রো করা প্রক্সি দিয়ে বদলে রাখে, ফলে কনটেক্সট পাশ কাটিয়ে যাওয়া কোনো রিকোয়েস্ট নেটওয়ার্ক ছোঁয়ার বদলে সশব্দে ব্যর্থ হয়।

একই প্যাটার্ন খাটে URL-এর জন্য `$mol_state_arg`, স্টোরেজের জন্য `$mol_state_local`, আর আপনার কম্পোনেন্ট `this.$` থেকে যা কিছু নেয় তার সবের ক্ষেত্রে।

`$mol_test_mocks`-ও আছে, ফাংশনের একটি তালিকা যা বান্ডলের প্রতিটি টেস্টের আগে কনটেক্সটের ওপর চলে — অন্য মডিউলের টেস্টের আগেও। সর্বত্র খাটে এমন নিয়মের জায়গা এটি, যেভাবে ফ্রেমওয়ার্ক নিজের মকগুলো নিবন্ধন করে: একটি স্টোরেজ-বদলি যা যা পায় তা রেখে দেয়, একটি লোকেল যা খালি ডিকশনারি ফেরত দেয়, আর উপরের ওই নেটওয়ার্ক-নিষেধ। একটিমাত্র কম্পোনেন্টের ফিক্সচার ডেটার জায়গা ওটি নয়।

## সময়

ফ্রেমওয়ার্কের নিজের টেস্টগুলো `$mol_after_timeout`, `$mol_after_frame` ও তাদের সহোদরদের জন্য মক নিবন্ধন করে, আর সেই মকগুলো আপনার বান্ডলেও আছে। `new this.$.$mol_after_timeout( ms, task )` দিয়ে বানানো টাইমার শিডিউল না হয়ে সারিতে যায়, আর `$mol_after_mock_warp()` সারিটি চালায়। নিজেই লুকিয়ে যায় এমন একটি টোস্ট ধরুন:

```typescript
@ $mol_mem toast( next?: string ) { return next ?? '' }

@ $mol_action notify( text: string ) {
	this.toast( text )
	new this.$.$mol_after_timeout( 3000, ()=> this.toast( '' ) )
}
```

টেস্টটি সময়কে হাতে করে এগিয়ে নেয়:

```typescript
'toast hides after the timer'( $ ) {
	const app = $my_greeter.make({ $ })
	app.notify( 'Saved' )
	$mol_assert_equal( app.toast(), 'Saved' )
	$mol_after_mock_warp()
	$mol_assert_equal( app.toast(), '' )
},
```

ভিউয়ের ভেতরে খালি `setTimeout` মক হয় না আর টেস্টের চেয়েও বেশি বাঁচে; কনটেক্সটের মাধ্যমে টাইমার বানানোর এটিও একটি কারণ।

## DOM-এর মধ্য দিয়ে

Node বান্ডলে `$mol_dom_context` একটি jsdom উইন্ডো, তাই ভিউ আসল এলিমেন্টে রেন্ডার হয়। যাচাইটি যখন স্টেট নিয়ে নয়, মার্কআপ নিয়ে, তখন এটি ব্যবহার করুন:

```typescript
'greets by name'( $ ) {
	const app = $my_greeter.make({ $ })
	app.name( 'Ada' )
	$.$mol_dom_context.document.body.appendChild( app.dom_node() )
	app.dom_tree()
	$mol_assert_equal( app.Hello().dom_node().textContent, 'Hello, Ada!' )
	app.destructor()
},
```

`dom_node()` এলিমেন্টটি বানায়, `dom_tree()` সাবট্রি রেন্ডার করে, আর `destructor()` ভিউটি ছেড়ে দেয় যাতে তার সেলগুলো টেস্টের চেয়ে বেশি না বাঁচে। সাব-ভিউ তার নাম থেকে যে অ্যাট্রিবিউট পায় — এখানে `[my_greeter_hello]` — সাব-ভিউ কল করার বদলে `querySelector` পছন্দ করলে সেটিই আপনার সিলেক্টর।

jsdom-এ দুটি গ্লোবাল নেই, যেগুলোর কাছে ইনপুট ফিল্ড আর জেসচার হাত বাড়ায়: `ShadowRoot` আর `PointerEvent`। এগুলো ছাড়া রেন্ডার হওয়া `$mol_string` একটি `ReferenceError` লগ করে আর খালি পড়ে থাকে, যদিও ট্রি-এর বাকিটা রেন্ডার হয়। jsdom উইন্ডো থেকে এগুলো ধার নিন; এটি প্রতিটি টেস্টের জন্য ডেটা-নিরপেক্ষ একটি নিয়ম, তাই এর জায়গা `$mol_test_mocks`-এ:

```typescript
$mol_test_mocks.push( $ => {
	const win = $.$mol_dom_context
	Object.assign( globalThis, {
		ShadowRoot: win.ShadowRoot,
		PointerEvent: win.PointerEvent ?? win.MouseEvent,
	} )
} )
```

## Node টেস্ট যা ধরে না

জ্যামিতি আর স্টাইলিং। দুটি ব্লক এক সারিতে বসছে কি না, কোনো প্যানেল স্ক্রিন ছাপিয়ে যাচ্ছে কি না, ডার্ক থিম পড়তে ভালো লাগছে কি না: এর কিছুই jsdom-এ নেই। যে লেআউটে হাত দিয়েছেন, তার জন্য মডিউলের `-/test.html` ব্রাউজারে খুলুন — এটি অ্যাপ মাউন্ট করে আর সেখানেই একই টেস্টগুলো চালায় — আর তাকিয়ে দেখুন।

## ব্যবহারিক নোট

- **নীরবতা মানেই ব্যর্থতা।** অ্যাসারশন ব্যর্থ হওয়া টেস্ট আর ঝুলে যাওয়া টেস্ট দেখতে একরকম: কোনো আউটপুট নেই আর প্রসেসটি বেঁচে আছে। শেষে `All tests passed` খুঁজুন; না থাকলে আগে শেষ অ্যাসারশনটি দেখুন। `async` টেস্ট এক সেকেন্ডে সীমিত।
- **ইচ্ছে করে একটা ভাঙুন।** কোনো রান যখন কিছুই ছাপে না, একটি অ্যাসারশন উল্টে দিয়ে নিশ্চিত করুন ব্যর্থতাটি দেখা যাচ্ছে। যে টেস্ট স্যুট ব্যর্থ হতেই পারে না, সেটি কিছুই মাপছে না।
- **লোকালাইজ করা স্ট্রিং যাচাই করবেন না।** ট্রি-তে `@` দিয়ে চিহ্নিত মানগুলো লোকেলের মধ্য দিয়ে সমাধান হয়, আর প্রতিটি টাটকা কনটেক্সটে লোকেল আবার গরম হয়। গঠন যাচাই করুন, লেবেলের টেক্সট নয়।
