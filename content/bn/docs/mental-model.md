# মানসিক মডেল

আপনি যদি React বা Vue থেকে আসেন, $mol-এ প্রথম কয়েকটা দিন কাটে এমন সব জিনিস খুঁজে: `computed`, `watch`, `useEffect`, `onMounted`, লাইফসাইকেল হুকের ভেতরে একটা `fetch` — যেগুলো আসলে নেই। এগুলো API-এর কোথাও লুকানো নয়; মডেলে এদের জায়গাই নেই। এই পৃষ্ঠাটি সেই মডেলের পাঁচ মিনিটের সংস্করণ। [ভিউ](#!section=docs/page=views) পড়ার আগে এটি পড়ুন, আর যখনই কোনো চেনা নাম হারিয়ে যাবে, ফিরে আসুন।

## পুল, পুশ নয়

কেউ না পড়লে কিছুই গণনা হয় না। ভিউ তার প্রপার্টিগুলো পড়ে রেন্ডার হয়; প্রতিটি প্রপার্টি যা দরকার তা পড়ে; নির্ভরতার শেকল এই পড়াগুলো থেকেই নিজে নিজে গড়ে ওঠে। ঘোষণা করার মতো কোনো সাবস্ক্রিপশন নেই, রেজিস্টার করার মতো কোনো `watch` নেই: পড়াটাই সাবস্ক্রিপশন।

```tree
$my_profile $mol_view
	sub /
		<= Name $mol_view
			sub / <= name \
```

```typescript
namespace $.$$ {
	export class $my_profile extends $.$my_profile {
		@ $mol_mem
		user() {
			return this.$.$mol_fetch.json( 'https://api.example.com/me' ) as { name: string }
		}
		name() {
			return this.user().name
		}
	}
}
```

`Name` রেন্ডার হতে গিয়ে `name()` পড়ে, `name()` পড়ে `user()`, আর `user()` নেটওয়ার্কে যায়। কেউ ভিউকে রিকোয়েস্টের কথা বলেনি, কেউ রিকোয়েস্টকে ভিউয়ের কথা বলেনি। `user()` বদলালে যারা এটি পড়েছিল সবাই পুনরায় গণনা হয়, আর কিছুই হয় না।

## কোনো লাইফসাইকেল নেই

`mounted` নেই, `useEffect` নেই, `created` নেই। একটি প্রপার্টি পড়ার মাধ্যমেই ডেটা চাওয়া হয়, আর ভিউ রেন্ডার হওয়ার সময় তার প্রপার্টিগুলো পড়ে। তাই উপরের উদাহরণটি ঠিক যে মুহূর্তে `$my_profile` স্ক্রিনে আসে সেই মুহূর্তেই ইউজার লোড করে, তার আগে নয়। ভিউ স্ক্রিন থেকে সরে গেলে আর কেউ `user()` পড়ে না, আর সেলটি ভিউয়ের সঙ্গেই ছেড়ে দেওয়া হয়।

"মাউন্টে ফেচ" প্যাটার্নের গোটা বিকল্প এটুকুই: ভিউ যা দরকার তা চায়, আর কখন চাওয়া হবে তা ফ্রেমওয়ার্ক ঠিক করে। লোডিং কোনো পৃষ্ঠার ইভেন্টের সঙ্গে জোড়া নয়; দৃশ্যমান থাকার সঙ্গে জোড়া।

## প্রপার্টি মানেই একটি সেল

ঐচ্ছিক আর্গুমেন্টসহ একটিমাত্র মেথড একই সঙ্গে গেটার, সেটার, গণিত মান ও স্টেট:

```typescript
@ $mol_mem
count( next?: number ) {
	return next ?? 0
}
```

আর্গুমেন্ট ছাড়া ডাকলে পড়ে, আর্গুমেন্টসহ ডাকলে লেখে। `@ $mol_mem` মেথডটিকে এমন একটি ক্যাশড সেলে পরিণত করে, যা পড়া কিছু বদলালে পুনরায় গণনা হয়। গণিত মান কেবলই এমন একটি `@ $mol_mem` মেথড যা অন্য মেথড পড়ে। ওয়াচারের দরকার নেই: সাইড ইফেক্ট একটি ইভেন্টের অধীন, আর ইভেন্ট হ্যান্ডলার হলো `@ $mol_action` দিয়ে চিহ্নিত একটি মেথড।

```typescript
@ $mol_mem
doubled() {
	return this.count() * 2
}

@ $mol_action
increment() {
	this.count( this.count() + 1 )
}
```

এই দুইয়ের প্রতিটির ভেতরে কী ঘটতে পারে, তার নিয়ম [স্টেট ও রিয়্যাক্টিভিটি](#!section=docs/page=state)-তে আছে।

## সিঙ্ক্রোনাস কোড, যা অপেক্ষা করে

উপরের `user()` দেখতে সিঙ্ক্রোনাস, আর লেখাও হয়েছে এমনভাবে যেন রেসপন্স আগে থেকেই হাজির। এটি কাজ করে কারণ প্রতিটি গণনা একটি ফাইবারের ভেতরে চলে। `this.$.$mol_fetch.json()` সেই ফাইবারকে সাসপেন্ড করে, আর রেসপন্স এসে গেলে ফ্রেমওয়ার্ক গণনাটি আবার শুরু করে। ততক্ষণ যে ভিউ `user()` পড়েছিল সেটি লোডিং স্টেট দেখায়; রিকোয়েস্ট ব্যর্থ হলে সেই একই ভিউ এররটি দেখায়। আপনি `isLoading` ফ্ল্যাগও লেখেন না, `try`/`catch`-ও না।

একই কৌশল যেকোনো অ্যাসিঙ্ক উৎসের জন্য খাটে। [ডেটা ফেচিং](#!section=docs/page=data) পুনরায় লোড করা ও ত্রুটি সামলানো ধাপে ধাপে দেখায়।

## সবকিছুই একটি ওভাররাইড

একটি `view.tree` ফাইল মেথড ঘোষণার তালিকা। কম্পোনেন্টের নিচের প্রতিটি লাইন সেই কম্পোনেন্টের একটি প্রপার্টি, ডিফল্ট মানসহ, আর নেস্টেড যেকোনো কম্পোনেন্টের প্রপার্টি যেখানে সেটি ব্যবহৃত হচ্ছে ঠিক সেখানেই এক লাইনে নতুন করে সংজ্ঞায়িত করা যায়। টেক্সট ইনপুটের প্লেসহোল্ডার হলো `$mol_string`-এর `hint` প্রপার্টি:

```tree
$my_search $mol_view
	sub /
		<= Query $mol_string
			hint \Search
			value? <=> query? \
```

বাড়ানোর মতো কোনো prop-তালিকা নেই, লেখার মতো কোনো র‍্যাপার নেই, রক্ষণাবেক্ষণের মতো কোনো ফর্ক নেই। কম্পোনেন্টের কোনো প্রপার্টি থাকলে আপনি বাইরে থেকেই সেটি সেট করতে পারেন।

## সোর্স কীভাবে পড়বেন

আগের অংশটি আসল প্রশ্নটিই তোলে: প্রপার্টির নাম যে `hint`, তা আপনি জানবেন কীভাবে? উত্তর হলো, আপনি দেখে নেবেন — আর ফ্রেমওয়ার্কটি এমনভাবে বানানো যাতে দেখে নেওয়া সস্তা হয়।

**ফ্রেমওয়ার্কের সোর্স আপনার সোর্সের পাশেই থাকে।** MAM ওয়ার্কস্পেসে `mol/string/string.view.tree` আর `my/hello/`-এর মাঝে এক ফোল্ডারের দূরত্ব। এটি `node_modules`-এ নেই, কোনো বান্ডলের ভেতরেও নেই; আপনি নিজে যেমন ফাইল লেখেন, ঠিক তেমনই একটি ফাইল।

**ক্লাসের নামই পথ।** `$mol_string` থাকে `mol/string/`-এ, `$mol_button_major` থাকে `mol/button/major/`-এ। প্রতিটি আন্ডারস্কোর একটি ফোল্ডার বিভাজক, তাই আপনার ট্রি-এর যেকোনো নামকে সবসময় খুলে দেখার মতো একটি ফোল্ডারে রূপান্তর করা যায়। [টুলিং](#!section=docs/page=tooling) পৃষ্ঠার এডিটর সাপোর্ট এই নামগুলো আপনার হয়ে সম্পূর্ণ করে দেয়।

**একটি কম্পোনেন্টের `.view.tree` হলো তার প্রপার্টির পূর্ণ তালিকা, ডিফল্টসহ।** মানের আকৃতিই তার ধরন বলে দেয়: `\` দিয়ে স্ট্রিং শুরু হয়, `/` দিয়ে লিস্ট, `*` দিয়ে ডিকশনারি, খালি সংখ্যা মানে সংখ্যা, `true` আর `false` বুলিয়ান, `null` মানে অনুপস্থিত, আর `<=` একটি সাব-ভিউ বা মালিকের কাছ থেকে নেওয়া একটি প্রপার্টি পরিচয় করায়। ইনপুটের জন্য `mol/string/string.view.tree`-এর যে অংশটুকু গুরুত্বপূর্ণ:

```tree
$mol_string $mol_view
	dom_name \input
	enabled true
	field *
		^
		disabled <= disabled false
		value <= value_changed? <=> value? \
		placeholder <= hint_visible <= hint \
	attr *
		^
		type <= type? \text
```

জোরে পড়ুন। `dom_name \input`: এই কম্পোনেন্ট একটি `input` এলিমেন্ট রেন্ডার করে। `enabled true`: একটি বুলিয়ান প্রপার্টি, ডিফল্টে চালু। `field *` হলো DOM এলিমেন্টের ফিল্ডের ডিকশনারি; বাঁ দিকের নামগুলো DOM-এর, ডান দিকের নামগুলো কম্পোনেন্টের, আর সবচেয়ে ডানেরটিই আপনি সেট করেন। তাই DOM-এর `placeholder` আসে `hint` থেকে, যার ডিফল্ট খালি স্ট্রিং; DOM-এর `value` হলো লেখনযোগ্য `value?` প্রপার্টি, আর `type` অ্যাট্রিবিউট হলো লেখনযোগ্য `type?`, যার ডিফল্ট `text`। একটি প্লেসহোল্ডার, একটি নিষ্ক্রিয় ইনপুট আর একটি পাসওয়ার্ড ফিল্ড আপনার ট্রি-তে হলো `hint`, `enabled false` আর `type \password`।

**টাইপড ইন্টারফেসও একই ট্রি থেকে তৈরি হয়।** `mol/string/-view.tree/string.view.tree.d.ts` একই প্রপার্টিগুলোকে TypeScript সিগনেচার হিসেবে তালিকাবদ্ধ করে, আর এই সাইটের [API রেফারেন্স](#!section=docs/page=api-mol-string) ওই ফাইল থেকেই তৈরি। তিনটিই মেলে, কারণ তিনটিই এক উৎস থেকে আসে।

**বেশিরভাগ কম্পোনেন্টের সঙ্গে একটি `demo/` ফোল্ডার ও একটি `readme.md` থাকে।** `mol/string/demo/demo.view.tree` ইনপুটটিকে দেখায় hint সহ, নিষ্ক্রিয় অবস্থায়, আর আগে থেকে বসানো মানসহ। কোনো কম্পোনেন্ট কোনো বিশেষ অবস্থায় দরকার হলে, তার সবচেয়ে কাছের ডেমোটি খুঁজে নিয়ে লাইনটি কপি করুন।

সব মিলিয়ে একটি প্লেসহোল্ডারে মিনিটখানেক লাগে:

```bash
ls mol | grep string
cat mol/string/string.view.tree
```

`$mol_string`-এর নিচে `hint \` দেখতে পাবেন, আর নিজের `$mol_string`-এর নিচে `hint \Search` লিখবেন।

## নাম

সবকিছুই `snake_case`: `view.tree`-এর প্রপার্টির নাম, TypeScript-এ মেথডের নাম, স্টাইলিংয়ের জন্য ফ্রেমওয়ার্ক DOM নোডে যে অ্যাট্রিবিউট বসায় সেগুলোও। সাব-ভিউ শুরু হয় বড় হাতের অক্ষরে (`Query`), মান শুরু হয় ছোট হাতের অক্ষরে (`query`)।

ট্রি-এর নাম আর ক্লাসের মেথডের নাম অক্ষরে অক্ষরে মিলতে হবে। ট্রি-তে `exchange_form` আর ক্লাসে `exchangeForm` দুটি সম্পর্কহীন প্রপার্টি: ক্লাসেরটি কখনো পড়াই হয় না, ট্রি-এরটি তার ডিফল্ট ধরে রাখে, আর এ কথা বলার মতো কোনো এরর নেই। কোনো ওভাররাইড যখন কিছুই করছে বলে মনে হয় না, প্রথমে এটিই দেখার জিনিস। স্ক্রিন ভুল অথচ কম্পাইলার চুপ — এমন এই ও অন্যান্য ঘটনাগুলো [সমস্যা সমাধান](#!section=docs/page=troubleshooting)-এ তালিকাবদ্ধ।
