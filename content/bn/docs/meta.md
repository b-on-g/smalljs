# মডিউল মেটাডেটা

মডিউলের কম্পোনেন্টের পাশাপাশি, একটি `name.meta.tree` ফাইল **বিল্ড ও ডিপ্লয় মেটাডেটা** ঘোষণা করে——যা কোনো একক ভিউ নয় বরং সামগ্রিকভাবে মডিউল সম্পর্কিত। অ্যাপ মডিউল এটির স্বাভাবিক জায়গা।

এই সাইটের `app.meta.tree` নিচে দেওয়া হলো:

```tree
include \/mol/offline/install
include \/bog/builderui/theme.css
deploy \/bog/smalljs/assets
```

## ডিরেকটিভ

- **`deploy \/path`**——নামোল্লিখিত ফাইল বা ফোল্ডারটি প্রোডাকশন বিল্ড আউটপুটে কপি করে। ডিপ্লয়কে বহন করতে হবে কিন্তু কোনো কোড ইমপোর্ট করে না এমন স্ট্যাটিক অ্যাসেটের জন্য ব্যবহার করুন——ছবি, ফন্ট, আইকন। এখানে `\/bog/smalljs/assets` লোগো ও `assets/`-এর নিচের অন্য ফাইলগুলো পাঠায়।
- **`require \/path`**——কোনো কোড কোনো মডিউলকে রেফারেন্স না করলেও সেটিকে জোর করে বান্ডলে ঢোকায়, সেই ক্ষেত্রের জন্য যেখানে ওই মডিউলের কোড এই `meta.tree` ধারণকারী মডিউলের কোডের **আগে** চলতে হবে। এটি একটি সাধারণ, উচ্চ-অগ্রাধিকার ডিপেন্ডেন্সি হিসেবে যুক্ত হয়। একটি মডিউল পাথ (`\/mol/wire/patch`) বা একটি একক ফাইল দুই-ই কাজ করে।
- **`include \/path`**——একই জোরপূর্বক অন্তর্ভুক্তি, কিন্তু যখন লোড অর্ডার গুরুত্বপূর্ণ নয় তখনের জন্য। মডিউলটি যুক্ত হয় কিন্তু অগ্রাধিকার কমানো হয়, তাই এটির ওপর নির্ভরশীল কোডের পরে লোড হয়। উদাহরণ: `include \/mol/offline/install` (সাইড ইফেক্ট হিসেবে একটি service worker রেজিস্টার করে) ও `include \/bog/builderui/theme.css` (একটি র স্টাইলশিট)।
- **`pack <name> git \<url>`**——একটি নেমস্পেসকে সেই git রিপোজিটরিতে ম্যাপ করে যেখান থেকে MAM এটি আনে, যেমন `pack mol git \https://github.com/hyoo-ru/mam_mol.git`। `$mol_*`, `$hyoo_*`, এবং আপনার নিজের প্যাকেজগুলো ঠিক এর মাধ্যমেই প্রকৃত কোডে রিজলভ হয়।

আদৌ কেন অন্তর্ভুক্তি জোর করতে হবে? বিল্ডার স্বয়ংক্রিয়ভাবে ডিপেন্ডেন্সি বের করে এবং শুধু আপনার কোড আসলে যা ব্যবহার করে তাই বান্ডল করে। মাঝেমধ্যে এমন একটি মডিউল দরকার হয় যা আপনার কোড রেফারেন্স *করে না*——যেমন এমন একটি অ্যাপ যা কম্পোনেন্টের একটি পুরো ক্যাটালগ বান্ডল করে যাতে সেগুলো রানটাইমে থাকে। `require` ও `include` ঠিক সেই ক্ষেত্রটিই কভার করে; এরা শুধু লোড অর্ডারে ভিন্ন।

## এটি কোথায় থাকে

`pack` ঘোষণাগুলো **ওয়ার্কস্পেস-রুট**-এর `.meta.tree`-তে থাকে——সেটি হলো ওয়ার্কস্পেস যত প্যাকেজ টানতে পারে তার প্রতিটির রেজিস্ট্রি। সেগুলো সেখানেই রাখুন, সাবমডিউলে নয়; একটি সাবমডিউলের নিজের `meta.tree`-তে শুধু তার জন্য নির্দিষ্ট `require`/`include`/`deploy` থাকা উচিত।
