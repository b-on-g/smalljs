# オフライン

$mol アプリはネットワークなしでも動き続けられます——オンラインで一度開けば、オフラインになった後も使えたままで、PWA としてインストールすることもできます。これは 1 つの組み込みモジュール `mol/offline/install` によるもので、どのデータ層とも独立しています。

## 何をするか

`mol/offline/install` は `$mol_offline` を実行し、これが **service worker**（`web.js`）をキャッシュプロキシとして登録します。静的アセットの成功した `GET`——アプリのバンドル、スタイル、画像——はすべて `$mol_offline` という名前のキャッシュに保存されます。次回の読み込みでは worker がそれらのレスポンスをキャッシュから直接返すので、アプリは瞬時に開き、キャッシュされたコピーへフォールバックすることで HTTP エラーや接続断を乗り切ります。アプリ全体がキャッシュ可能でこの方法で提供されるため、ブラウザは **PWA としてのインストール** を提案できます。

## 有効化のしかた

アプリの `*.meta.tree` に 1 行を加えます:

```tree
include \/mol/offline/install
```

この強制 include はモジュールをバンドルに取り込み、その service worker が副作用として登録されます——他のコードがそれを参照する必要はありません。`include` の仕組みについては[モジュールメタデータ](#!section=docs/page=meta)を参照してください。

ブラウザからの実行時の要件が 2 つあります:

- **HTTPS**（開発では `localhost`）で配信すること——さもないと service worker は動作を拒否します。
- アプリをインストール可能にするため、ウェブアプリの manifest を用意すること。

## これは何で*ない*か

オフラインキャッシュは *1 つの* クライアントをネットワークなしで動かし続けます。クライアント*間*でデータを同期するものでは**ありません**。クエリ文字列付きのリクエストは素通しされ、`GET` 以外のリクエストはキャッシュされません。複数のクライアントやデバイスが同じライブで編集可能なデータを——競合のないマージで——共有する必要があるときは、それは別の課題であり、独立した [Giper Baza](#!section=docs/page=giper-baza) プロジェクトが扱います。
