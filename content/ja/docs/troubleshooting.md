# トラブルシューティング

このページの項目はどれも同じ形をしています。ビルドは通り、監査もきれいで、コンソールは静か、それなのに画面は空っぽか、意図したものと違う。コンパイラがこれらの間違いを見つけられないのは、どれも正しいプログラムであり、たまたま別のコンポーネントを記述しているだけだからです。自分が見ているものに近い見出しを探してください。その下に原因と直し方があります。

## プロパティのオーバーライドが何も起きない、エラーも出ない

`view.tree` の名前とクラスのメソッド名が食い違っています。多くは大文字小文字の違いです。ツリーでは `exchange_form`、クラスでは `exchangeForm`。これは二つのプロパティです。クラスのほうは決して呼ばれず、ツリーのほうはデフォルトのまま残り、誰もそれを知らせてくれません。

名前はどこでも `snake_case` で、一文字たがわず一致していなければなりません。`.view.ts` を編集したら、どのオーバーライドも実在するプロパティを指しているか確かめてください。突き合わせる一覧は、ツリーの隣に生成される `-view.tree/*.view.tree.d.ts` です。

## 入力欄にプレースホルダーや無効化、type を付けたい

どれも `$mol_string` のプロパティです。プレースホルダーは `hint`、無効な状態は `enabled`、入力の種類は `type`。入力を使っているその場で設定します。

```tree
<= Password $mol_string
	hint \Password
	type \password
	enabled <= can_edit true
	value? <=> password? \
```

他のどのコンポーネントの他のどのプロパティも、見つけ方は同じです。その `.view.tree` を開くこと。[ソースの読みかた](#!section=docs/page=mental-model/Docs.Body=%E3%82%BD%E3%83%BC%E3%82%B9%E3%81%AE%E8%AA%AD%E3%81%BF%E3%81%8B%E3%81%9F)が示すとおりです。

`attr *` は、コンポーネントがまだモデル化していない本物の DOM 属性のためのもので、それ自身の落とし穴があります。最初の行が `^` でないブロックは、基底の属性辞書をまるごと置き換えてしまうので、そう書かれた `$mol_button` は `disabled`、`role`、`tabindex` を失います。継承するにはブロックを `^` で始め、そのあとに自分のキーを足してください。

```tree
attr *
	^
	data_kind \primary
```

## 単語が一文字ずつバラバラに描画される

リストが期待される場所に文字列が渡され、その文字列が一文字ずつ展開されました。文字列は `\` で始まり、リストは `/` で始まります。よくあるのは、リストである `sub` です。

```tree
sub / <= label \Hello
```

## 画面が空っぽなのに、テストは緑

オーバーライドが `.view.ts` から抜け落ちました。ツリーはどのプロパティにもデフォルトを与えるので、クラスが `rows()` を再定義しなくなっても TypeScript は満足し、リストは空のまま描画されます。モデルだけを調べるテストは、モデルが無事なので緑のままです。

画面が依存しているオーバーライドには、ユーザーが見るものを読むテストを書いてください。`rows()`、`sub()`、サブビューの `title()`、あるいは DOM です。[テスト](#!section=docs/page=testing)がその両方を示します。

## データがいつまでも読み込まれず、コンポーネントが読み込み状態のまま固まる

`@ $mol_mem` のメソッドが promise を値として返しています。`fetch( uri ).then( ... )`、`async` メソッド、あるいは `$mol_wire_async( this ).load()` の結果です。セルの中の promise は、誰にとっても「まだ計算中」と読めます。そして解決するとセルは再計算され、新しい promise を作り出します。ネットワークは動いているのに、ビューは結果を一度も見ません。

正しい形は同期的です。セルの中で `this.$.$mol_fetch.json( uri )` を呼び、パースされた値を返します。ファイバーは応答が届くまで中断し、それからセルを走らせ直すので、promise があなたのコードに現れることはありません。非同期の仕事をどこか別の場所でやらざるをえないときは、その結果を別の状態セルに置き、エフェクトにはフラグかキーを返させてください。promise を返させてはいけません。

もう一つの原因は握りつぶされたエラーです。セルの中の `try`/`catch` が、本物の失敗と一緒に中断まで捕まえてしまうのです。`Promise` であるものは再スローするか、その判定を代わりにやってくれる `$mol_fail_catch` を使ってください。

## 循環購読（Circular subscription）

`@ $mol_mem` のメソッドが別のセルへ書き込んだか、自分が読んだものを結果的に無効化する副作用を行いました。計算は読んで返すだけです。書き込み、ネットワーク、タイマー、DOM は `@ $mol_action` のハンドラーに属します。同じメッセージのもう一つの出どころは、子への `<=>` バインディングと、その同じ子へ委譲するクラスのメソッドの組み合わせです。次の項目で説明します。

## Maximum call stack（コールスタックがあふれる）

これを生む形は二つあります。一つ目。ツリーで子に `tab? <=> tab?` があり、クラスに `tab() { return this.Head().tab() }` がある場合です。子が所有者に尋ね、所有者が子に尋ねます。委譲する先の子への `<=>` を外してください。

二つ目。サブビューを自分のクラスに付け替え、そのクラスがツリーに並んでいるプロパティで `super` を呼んでいる場合です。その `super` は基底の実装ではなく、並んでいるバインディングのためにツリーが生成したスタブで、スタブは所有者へ委譲し返します。代わりに、元の実装へ明示的に委譲してください。下にある付け替えの項目を参照してください。

## 大文字で書いた値が TypeScript からオーバーライドできない

`<= Label* \` は `Label` という名前のメソッドを生成するので、クラスの `label()` は別のメソッドです。サブビューは大文字、値は小文字で始まり、生成されるメソッドの名前を決めるのはツリーでの大文字小文字です。

## 入れ子のリストで、どの行にも同じ項目が出る

キー付きのサブビューの中にあるキー付きのサブビューは、自分のキーを受け取りません。`Row*0` の中の `Cell*0` は、どの行でもキー `0` で描画されます。行を独立したコンポーネントに切り出し、そのデータはプロパティで渡してください。そして外側のビューのキーは `Row*0` ではなく `Row*` にします。

## サブビューのクラスを変えたら中身が消えた

`Pre* $mol_text_code` を `Pre* $my_code` に付け替えると、基底のツリーがそれに対して宣言していたバインディングが落ちるので、書き直さなければなりません。ところが `text <= pre_text* \` と並べると、空のスタブができて `$mol_text` の本物の `pre_text` を覆い隠します。`super`——それがそのスタブです——に頼らず、クラスの中で委譲してください。

```typescript
pre_text( index: number ) {
	return $mol_text.prototype.pre_text.call( this, index )
}
```

## 基底コンポーネントの view.ts のメソッドがサブクラスに見当たらない

ツリーの `$my_child $my_base` が継承するのは `base.view.tree` から生成されたクラスであって、あなたが `base.view.ts` に書いたクラスではありません。そこで定義したメソッドは子に届かず、TypeScript は「ない」と報告します。複数のビューで共有するロジックは、ツリーを持たない素の `.ts` ファイルの `namespace $` に置いてください。`$mol_view` 自身がそう書かれています。

## 同じ view.tree ファイルで宣言した基底コンポーネントが振る舞いを失う

一つのツリーファイルが基底と、それを継承するクラスの両方を宣言していると、子にとっては基底の `.view.ts` の本体が素通りされます。`.view.ts` を持つ基底には、専用のフォルダを与えてください。

## サブビューとその中のコンポーネントの間でスタイルが漏れる

`$my_app` の中の `Nav $my_app_nav` は、サブビューとコンポーネントの両方に同じ `my_app_nav` 属性を付けるので、一つのセレクタが両方に当たります。サブビューには、クラス名の末尾を繰り返さない名前を付けてください。たとえば `Nav_row` です。

## false の属性を狙ったセレクタが決してマッチしない

`false` に設定された真偽値の属性は要素から取り除かれるので、`[expanded="false"]` は何にもマッチしません。条件付きの描画は CSS の仕事ではありません。サブビューのファクトリをオーバーライドし、そのビューを持たないバリアントでは `null` を返してください。

## スタイルに書いた数値が何も変えない

`style *` の中の数値には、すべて `px` が付け足されます。`flexGrow 1` は `flex-grow: 1px` になり、ブラウザーはそれを捨てます。単位のない値は文字列で書いてください。`flexGrow \1` です。

## スクロールビューの二つの子が重なって表示される

`$mol_scroll` が持てる子はちょうど一つです。子を `$mol_view` か `$mol_list` で包み、それをスクロールに渡してください。

## minimal_height を変えても見た目が変わらない

`minimal_height` は、仮想化された `$mol_list` が行を描画する前に見積もるために使う数値で、高さを設定するものではありません。高さは `.view.css.ts` で設定します。

## 埋め込んだコンポーネントがページを横へ押し広げる

よそのレイアウトの中にマウントされたビューは、デフォルトでは中身より小さくは縮みません。ルートのスタイルに `minWidth: 0` を与えて、周りの要素と同じように押し縮められるようにしてください。

## 外部の CSS が自分のコンポーネントに効かない

`dom_name` を持たないコンポーネントは、自分のクラス名を持つ要素として描画されます。CSS フレームワークにとって、それは未知のインライン要素です。タグを明示してください。`$mol_button` は `dom_name` を持たないので、外部の CSS でスタイルを当てたいボタンには `dom_name \button` が要ります。

## 現在のページへのリンクをクリックすると URL が消える

`arg *` を持つ `$mol_link` はトグルです。URL がすでに一致しているページでは、クリックがそのキーを取り除きます。移動するだけのリンクにしたいなら、`uri_off <= uri` を付けたサブクラスにしてください。クリックで同じルートを読み込み直すには、ハンドラーから `$mol_state_arg.value()` を呼び、イベントを `preventDefault` します。

## 入力のハンドラーが描画のたびに走る

`$mol_string` のサブクラスに追加した `prop?` が、基底がすでに使っているプロパティと同じ名前になっています。`enter`、`submit`、`hint`、`value`、`keyboard` など。新しい名前を足す前に、基底のツリーと突き合わせてください。

## 値のセッターで投げたエラーが表示されない

`$mol_string` は `value?` からの例外を捕まえて入力欄の `setCustomValidity` に渡すので、ネイティブのフォーム検証としてしか現れません。エラーは自分の経路で伝えてください。ステータス行か、メッセージ用のサブビューです。

## キー付きのハンドラーのバインディングが「ない」と言われる

キー付きのサブビューに書いた `event_click? <=> pick*? null` は、`pick` のスタブを生成しません。ツリーのルートに自分で `pick*? null` と宣言し、クラスで実装してください。

## 使った覚えのないモジュールがバンドルに入っている

ビルダーは、ソースのテキストから `$mol_name` というトークンを拾って依存を割り出します。文字列リテラルの中のトークンも、`/** */` のドキュメントコメントの中のトークンも、コードの中のものと同じだけ数えられます。ドキュメントコメントに例として挙げた名前が、そのモジュールをまるごと引っぱってきて、あなたが一度も触っていないファイルで不具合が表に出ます。例やメモは `$` を付けずに書くか、代わりにフォルダ名を書いてください。

## 次へ

ここに並んだものの多くは、一つの規則に行き着きます。ツリーの名前が契約であり、コンパイラは型を調べても名前は調べない、ということです。ツリーがなぜオーバーライドの一覧なのかは[メンタルモデル](#!section=docs/page=mental-model)が説明し、黙ったままの間違いを捕まえるテストは[テスト](#!section=docs/page=testing)が示します。
