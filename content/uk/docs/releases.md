# Релізи

$mol постачається **безперервно**. Замість нарізати нумеровані версії, фреймворк постачається прямо з монорепозиторію [mam_mol](https://github.com/hyoo-ru/mam_mol) — кожна злита зміна одразу доступна кожному, хто на ній будує. Інструмент збірки MAM завжди підтягує поточні джерела, тож немає кроку оновлення й матриці версій, яку треба узгоджувати.

## Стеження за змінами

- **Історія комітів** — [коміти mam_mol](https://github.com/hyoo-ru/mam_mol/commits/master) — це канонічний журнал змін.
- **Історія по модулях** — кожна тека компонента на GitHub має власний журнал комітів, тож ви можете стежити лише за частинами, які використовуєте.
- **Спільнота DEV** — помітні доповнення й статті поширюються під [тегом #mol](https://dev.to/t/mol).

## Що це означає на практиці

Оскільки немає ламких меж релізів, фреймворк надає перевагу зворотно сумісній еволюції: компоненти набувають можливостей без перейменування, а типізовані інтерфейси `view.tree` виводять несумісності на етапі компіляції, а не під час виконання. Якщо збірка перестає компілюватися після оновлення, помилки TypeScript вказують прямо на те, що змінилося.
