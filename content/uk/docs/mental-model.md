# Ментальна модель

Якщо ви прийшли з React чи Vue, перші дні в $mol минають у пошуках того, чого тут немає: `computed`, `watch`, `useEffect`, `onMounted`, `fetch` у хуку життєвого циклу. Вони не заховані десь в API — для них просто немає місця в моделі. Ця сторінка — п'ятихвилинна версія цієї моделі. Прочитайте її перед [Видами](#!section=docs/page=views) і повертайтеся, коли чергове знайоме ім'я не знайдеться.

## Тягнемо, а не штовхаємо

Ніщо не обчислюється, доки цього хтось не прочитає. Подання малюється, читаючи свої властивості; кожна властивість читає те, що потрібно їй; ланцюг залежностей збирається з цих читань сам. Немає підписки, яку треба оголосити, і немає `watch`, який треба зареєструвати: читання і є підпискою.

```tree
$my_profile $mol_view
	sub /
		<= Name $mol_view
			sub / <= name \
```

```typescript
namespace $.$$ {
	export class $my_profile extends $.$my_profile {
		@ $mol_mem
		user() {
			return this.$.$mol_fetch.json( 'https://api.example.com/me' ) as { name: string }
		}
		name() {
			return this.user().name
		}
	}
}
```

Рендеринг `Name` читає `name()`, `name()` читає `user()`, `user()` іде в мережу. Ніхто не розповідав поданню про запит і ніхто не розповідав запиту про подання. Коли `user()` змінюється, переобчислюється все, що його читало, і більше нічого.

## Жодного життєвого циклу

Немає ні `mounted`, ні `useEffect`, ні `created`. Дані запитуються читанням властивості, а свої властивості подання читає тоді, коли малюється. Тож приклад вище завантажує користувача тієї миті, коли `$my_profile` з'являється на екрані, і не раніше. Коли подання йде з екрана, `user()` більше ніхто не читає, і комірка звільняється разом із поданням.

Це і є вся заміна шаблону «завантажити на монтуванні»: подання просить те, що йому потрібно, а фреймворк вирішує, коли питати. Завантаження прив'язане не до події сторінки, а до того, що подання видно.

## Властивість — це комірка

Один метод із необов'язковим аргументом — це водночас гетер, сетер, обчислюване значення і стан:

```typescript
@ $mol_mem
count( next?: number ) {
	return next ?? 0
}
```

Виклик без аргументу читає, з аргументом — записує. `@ $mol_mem` перетворює метод на кешовану комірку, яка переобчислюється, коли змінилося щось із прочитаного нею. Обчислюване значення — це просто метод із `@ $mol_mem`, що читає інші методи. Спостерігач не потрібен: побічний ефект належить події, а обробник події — це метод, оздоблений `@ $mol_action`.

```typescript
@ $mol_mem
doubled() {
	return this.count() * 2
}

@ $mol_action
increment() {
	this.count( this.count() + 1 )
}
```

[Стан і реактивність](#!section=docs/page=state) описує правила того, що дозволено всередині кожного з двох.

## Синхронний код, що вміє чекати

`user()` вище виглядає синхронним і написаний так, ніби відповідь уже є. Це працює, бо кожне обчислення виконується у волокні. `this.$.$mol_fetch.json()` призупиняє це волокно, а фреймворк перезапускає обчислення, щойно надійшла відповідь. Доти подання, що прочитало `user()`, показує стан завантаження; якщо запит упав, те саме подання показує помилку. Ви не пишете ні прапорця `isLoading`, ні `try`/`catch`.

Той самий механізм обслуговує будь-яке асинхронне джерело. [Отримання даних](#!section=docs/page=data) проходить перезавантаження й обробку помилок.

## Усе — це перевизначення

Файл `view.tree` — це список оголошень методів. Кожен рядок під компонентом — це його властивість зі значенням за замовчуванням, і будь-яку властивість вкладеного компонента можна перевизначити просто там, де його використано, одним рядком. Placeholder у текстового поля — це властивість `hint` у `$mol_string`:

```tree
$my_search $mol_view
	sub /
		<= Query $mol_string
			hint \Search
			value? <=> query? \
```

Немає списку props, який треба розширювати, немає обгортки, яку треба писати, і немає форка, який треба підтримувати. Якщо в компонента є властивість, її можна задати ззовні.

## Як читати вихідники

Попередній розділ порушує головне питання: звідки ви знаєте, що властивість зветься `hint`? Відповідь — ви дивитеся, а фреймворк побудований так, щоб дивитися було дешево.

**Вихідники фреймворка лежать поруч із вашими.** У робочому просторі MAM `mol/string/string.view.tree` — за одну теку від `my/hello/`. Він не в `node_modules` і не всередині бандла; це такий самий файл, які ви пишете самі.

**Ім'я класу — це шлях.** `$mol_string` живе в `mol/string/`, `$mol_button_major` — у `mol/button/major/`. Кожне підкреслення — це роздільник тек, тож ім'я з вашого дерева завжди перетворюється на теку, яку можна відкрити. Підтримка редактора зі сторінки [Інструментарій](#!section=docs/page=tooling) дописує ці імена за вас.

**`.view.tree` компонента — це повний список його властивостей зі значеннями за замовчуванням.** Форма значення каже про тип: `\` починає рядок, `/` — список, `*` — словник, голе число — це число, `true` і `false` — булеві, `null` означає відсутність, а `<=` вводить підвид або властивість, узяту у власника. Ось та частина `mol/string/string.view.tree`, що важлива для поля вводу:

```tree
$mol_string $mol_view
	dom_name \input
	enabled true
	field *
		^
		disabled <= disabled false
		value <= value_changed? <=> value? \
		placeholder <= hint_visible <= hint \
	attr *
		^
		type <= type? \text
```

Прочитайте вголос. `dom_name \input`: цей компонент малюється елементом `input`. `enabled true`: булева властивість, увімкнена за замовчуванням. `field *` — це словник полів DOM-елемента; імена ліворуч належать DOM, імена праворуч — компоненту, і найправіше з них ви й задаєте. Тож DOM-івський `placeholder` береться з `hint`, порожнього рядка за замовчуванням; DOM-івський `value` — це записувана властивість `value?`, а атрибут `type` — записувана `type?`, за замовчуванням `text`. Placeholder, вимкнене поле й поле для пароля — це `hint`, `enabled false` і `type \password` у вашому дереві.

**Типізований інтерфейс генерується з того самого дерева.** `mol/string/-view.tree/string.view.tree.d.ts` перелічує ті самі властивості сигнатурами TypeScript, а [довідник API](#!section=docs/page=api-mol-string) на цьому сайті зібраний із цього файлу. Усі троє узгоджені, бо всі троє походять з одного джерела.

**Більшість компонентів має теку `demo/` і `readme.md`.** `mol/string/demo/demo.view.tree` показує поле з підказкою, вимкнене й із наперед заданим значенням. Коли компонент потрібен у якомусь стані, знайдіть найближче демо й скопіюйте рядок.

Разом це вкладає placeholder приблизно у хвилину:

```bash
ls mol | grep string
cat mol/string/string.view.tree
```

Ви бачите `hint \` під `$mol_string` і пишете `hint \Search` під своїм `$mol_string`.

## Імена

Усе в `snake_case`: імена властивостей у `view.tree`, імена методів у TypeScript, атрибути, які фреймворк вішає на DOM-вузли для стилізації. Підвиди починаються з великої літери (`Query`), значення — з малої (`query`).

Ім'я в дереві й ім'я методу в класі мають збігатися літера в літеру. `exchange_form` у дереві та `exchangeForm` у класі — це дві ніяк не пов'язані властивості: класову ніхто не читає, деревна лишається зі значенням за замовчуванням, і жодна помилка про це не скаже. Коли перевизначення ніби нічого не робить, перевіряти треба насамперед це. [Розв'язання проблем](#!section=docs/page=troubleshooting) перелічує цей та решту випадків, коли на екрані не те, а компілятор мовчить.
