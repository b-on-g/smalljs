# Маршрутизація

Маршрутизація в $mol — не окрема бібліотека: URL — це просто ще один шматок реактивного стану. Читайте його, записуйте — і подання реагують так само, як реагують на будь-яку комірку. Кнопка «назад», глибокі посилання й посилання, якими можна ділитися, — усе це задарма.

## URL як стан

`$mol_state_arg` надає параметри URL як реактивні значення. Прив'яжіть один до властивості — і адресний рядок стане вашим джерелом істини:

```typescript
namespace $.$$ {
	export class $my_app extends $.$my_app {
		@ $mol_mem
		page( next?: string ) {
			return $mol_state_arg.value( 'page', next ) ?? 'home'
		}
	}
}
```

Читання `page()` повертає поточне значення; виклик `page('about')` виконує перехід. Усе, що читає `page()`, перемальовується при зміні — зокрема й кнопка «назад» браузера, яка оновлює комірку за вас.

## Перемикання екранів

Поєднайте маршрутизоване значення зі звичайним `switch`, щоб вибрати, що малювати. Оскільки подання [ліниві](#!section=docs/page=rendering), екрани, які ви не показуєте, ніколи не будуються:

```typescript
@ $mol_mem
body_content() {
	switch ( this.page() ) {
		case 'about': return [ this.About() ]
		case 'docs': return [ this.Docs() ]
		default: return [ this.Home() ]
	}
}
```

## Посилання, що встановлюють аргументи

У `view.tree` посилання може встановлювати аргументи URL декларативно — клік по ньому виконує перехід без обробника:

```tree
<= About_link $mol_link
	arg *
		page \about
	sub / <= about_label \About
```

`$mol_link` також позначає себе активним (`mol_link_current`), коли його аргументи збігаються з поточним URL, тож підсвічування поточної сторінки не потребує додаткового стану.

## Кілька параметрів

Аргументи незалежні, тож екран може маршрутизуватися за кількома одразу. Саме цей сайт документації маршрутизується і за `section`, і за `page`:

```tree
<= Guide_link $mol_link
	arg *
		section \docs
		page \views
```

Кожен ключ здійснює повний обіг через URL, тож будь-яке подання за побудовою можна поширювати й додавати в закладки. Встановлення одного аргументу лишає інші недоторканими, що робить глибокі посилання — конкретний розділ *і* сторінку *і* якір — лише питанням встановлення потрібних вам ключів.

## Стан, якому не місце в URL

Не кожен шматок стану належить адресному рядку. Для значень, що мають зберігатися локально, але не засмічувати посилання — згорнута бічна панель, чернетка — використовуйте `$mol_state_local`, що зберігає в `localStorage` з тією самою формою гетера/сетера:

```typescript
@ $mol_mem
sidebar_open( next?: boolean ) {
	return $mol_state_local.value( 'sidebar_open', next ) ?? false
}
```

Звертайтеся до `$mol_state_arg`, коли стан має бути поширюваним; до `$mol_state_local`, коли його треба лише запам'ятати.
