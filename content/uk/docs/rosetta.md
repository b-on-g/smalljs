# З React, Vue та Svelte

Якщо ви будували інтерфейси на React, Vue чи Svelte, ви вже розумієте більшість того, що робить $mol — просто назви інші. Ці фреймворки чудові й популярні недарма; ця сторінка — таблиця перекладу, а не змагання, щоб ви швидко почувалися як удома.

## Карта понять

| Поняття | React | Vue | Svelte | $mol |
|------|-------|-----|--------|------|
| Компонент | функція / клас | SFC (`.vue`) | файл `.svelte` | `.view.tree` + `.view.ts` |
| Локальний стан | `useState` | `ref` / `reactive` | `let x` | `@ $mol_mem` |
| Похідне значення | `useMemo` | `computed` | `$: y = …` | `@ $mol_mem` (читає інші комірки) |
| Побічний ефект | `useEffect` | `watchEffect` | `$: { … }` | `@ $mol_action` (явний, ніколи не автоматичний) |
| Props | props | props | `export let` | прив'язки у `view.tree` |
| Подія | `onClick` | `@click` | `on:click` | `click? <=> handler?` |
| Двобічне введення | контрольований input | `v-model` | `bind:value` | `value? <=> field?` |
| Список | `items.map()` | `v-for` | `{#each}` | `Row*` із ключем |
| Умова | `cond && …` | `v-if` | `{#if}` | присвоїти `null`, щоб прибрати |
| Спільний стан | Redux / Context | Pinia / provide | store'и | будь-який об'єкт із `@ $mol_mem` |
| Маршрутизація | React Router | Vue Router | SvelteKit | `$mol_state_arg` |
| Стилізація | CSS-in-JS | `<style>` зі скоупом | `<style>` | типізований `.view.css.ts` |

## Що зазвичай здається новим

- **Реактивність автоматична й неопційна.** Як `ref` у Vue чи `$:` у Svelte, значення `@ $mol_mem` оновлює своїх читачів само — але немає масиву залежностей, який треба підтримувати, і ніде немає ручної підписки.
- **Ефекти відокремлені від обчислень.** React зводить похідні й ефекти в хуки; $mol тримає їх окремо: `@ $mol_mem` лише обчислює, `@ $mol_action` виконує ефекти. Саме цей поділ прибирає більшість загадок «чому це виконалося двічі?».
- **Стан — це просто об'єкти.** Немає окремої бібліотеки сховища, яку треба впроваджувати — спільне значення це реактивна властивість на будь-якому об'єкті, тож глобальний стан і стан компонента працюють однаково.
