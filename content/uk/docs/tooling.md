# Інструментарій

$mol працює в будь-якому редакторі, але невеликий набір інструментів робить `.view.tree` і типізовані стилі значно зручнішими: генератор проєктів, мовний сервер, інтеграції з редакторами Zed і VS Code та скіл, який навчає LLM-асистентів фреймворку.

## Генерація проєкту

`create-view-tree-lsp` створює готовий до запуску модуль $mol, щоб ви не збирали шаблонний код вручну:

```bash
npx create-view-tree-lsp bog/myapp
```

Запускати з кореня своєї копії MAM: шляхи модулів відлічуються звідти, там само проєкту й жити. Поза воркспейсом команда попередить, а не залишить з'ясовувати це на першій збірці.

Аргумент — шлях модуля (`namespace/name` або еквівалентне `bog_myapp`). Він записує `view.tree`, `view.ts`, `view.css.ts` та `index.html` для працюючого застосунку, плюс GitHub Actions для його розгортання.

Усе, що генератор уміє покласти, кладеться за замовчуванням. Ви називаєте лише те, чого не хочете:

```bash
npx create-view-tree-lsp bog/myapp --no-tauri --no-backend
```

- `--no-baza` — local-first сховище **Гіпер База**
- `--no-docker` — налаштування **Docker** з `docker-compose.yml` і конфігом nginx
- `--no-tauri` — десктопна оболонка **Tauri**
- `--no-backend` — REST-бекенд `$mol_server` зі сховищем `node:sqlite` і спільним типом елемента на TypeScript
- `--no-prerender`, `--no-seo` — видимість для пошуковиків, описана нижче в розділі [Неперервна інтеграція](#!section=docs/page=tooling/Docs.Body=%D0%9D%D0%B5%D0%BF%D0%B5%D1%80%D0%B5%D1%80%D0%B2%D0%BD%D0%B0%20%D1%96%D0%BD%D1%82%D0%B5%D0%B3%D1%80%D0%B0%D1%86%D1%96%D1%8F)

Незнайомий прапорець обриває запуск, тож одрук не залишить у проєкті зайвого мовчки.

Генератор — це тонка обгортка над CLI мовного сервера, тож `npx view-tree-lsp create bog/myapp` робить те саме безпосередньо.

## Переклади

Переклади лежать поруч зі своїм модулем, у `<модуль>/<імʼя>.locale=<lang>.json`. Кодові так зручно, перекладачеві — ні: замість одного списку фраз він отримує тридцять дрібних файлів.

**[$yuf_localizer](https://zerkalica.github.io/yuf/#!demo=yuf_localizer_demo)** закриває цей розрив. Вкажіть йому адреси проєктів і коди мов — і він покаже всі ключі одним списком із пошуком, позначаючи ті, до яких ще не дійшли руки: ключі, що є лише англійською, змінені, але не зафіксовані, і застарілі, яких у проєкті вже немає. Переклади тримаються у браузері, доки ви їх не вивантажите, тож між заходами нічого не губиться.

Коли перекладач закінчив, вивантажте результат і розкладіть його назад по модулях:

```bash
# з кореня MAM
npx view-tree-lsp locale bog/myapp/app/- --exclude=mol --update
```

Аргументом можна дати і теку, і окремий файл локалі. Прапорці:

- `--include=` приймає частину шляху й лишає тільки модулі, чий шлях її містить; повторювати можна скільки завгодно разів
- `--exclude=` навпаки пропускає такі — `--exclude=mol` залишить пакети самого фреймворка недоторканими
- `--update` дописує в наявні файли: значення з джерела перемагають, а ключі, яких у ньому немає, лишаються
- `--dry` показує план і нічого не записує

Ключ несе шлях до свого модуля, тому `$my_page_greeting` потрапить у `my/page/page.locale=ru.json` — поруч із джерелами, яким належить. А от обчислити цей модуль складніше, ніж здається: `_` розділяє і теки, і слова, тож «найдовший збіг шляху» — хибна відповідь. У `$my_page_lang_hint` властивість починається на `lang`, і справжній сусідній підмодуль `my/page/lang` забрав би ключ собі. Тому команда питає в кожного кандидата, які ключі він оголосив — MAM записує саме їх у його файл локалі в `-view.tree`, — і віддає ключ власникові.

## Неперервна інтеграція

Генератор записує GitHub Actions у `.github/workflows/`, тож новий проєкт розгортається й релізиться без додаткового налаштування.

`deploy.yml` запускається на кожен push. Він збирає застосунок за допомогою `hyoo-ru/mam_build`, публікує `app/-` у **GitHub Pages** з `main` і дає кожній гілці `feature/*` власну папку попереднього перегляду — вона видаляється автоматично, коли гілку видаляють.

### SEO

Обидва ввімкнені за замовчуванням і обидва спрацьовують за тегами `v*`:

- **`--no-prerender`** прибирає крок, який рендерить перелічені вами екрани (наприклад, `home`) у статичний HTML через `b-on-g/mol-prerender-action` — саме те, завдяки чому краулери й прев'ю посилань бачать справжній контент.
- **`--no-seo`** прибирає рантайм `$bog_seo`: роутер за pathname з картою сайту, `robots.txt`, `llms.txt` і вбудовуванням метаданих на кожну сторінку. Задача обслуговує збірку, вивантажує канонічний предрендерений HTML і загортає його назад у деплой.

Вони роблять одне й те саме і пишуть в одну теку, тож у `deploy.yml` потрапляє лише один: `$bog_seo`, поки він увімкнений, і prerender-action, щойно ви передали `--no-seo`. Лишайте `$bog_seo`, коли потрібні карти сайту й метадані на кожну сторінку, і спускайтеся до prerender-action, коли вся робота — жменька публічних екранів.

### Десктоп Tauri

З опцією Tauri `tauri.yml` збирає десктопні бінарники на теги `v*` (або на вимогу) через повторно використовуваний воркфлоу `b-on-g/tauri-mol-workflow-template`, з того самого модуля, що ви розгортаєте у веб.

## Мовний сервер

`view-tree-lsp` — це реалізація Language Server Protocol для формату `view.tree`. Запускайте його на вимогу через npx, без глобального встановлення:

```bash
npx view-tree-lsp@latest
```

Він сканує ваш робочий простір і дає будь-якому редактору з підтримкою LSP:

- автодоповнення для компонентів `$mol_*` і компонентів та властивостей, визначених у вашому власному проєкті
- підказки властивостей у межах компонента під курсором
- структуру оголошень компонентів для навігації
- живі оновлення в міру зміни файлів

Оскільки він говорить мовою LSP, ви можете спрямувати language-client будь-якого редактора на `npx view-tree-lsp`. Дві інтеграції нижче налаштовують його за вас.

## Zed

Розширення **View Tree Syntax Highlighting for $mol** обʼєднує граматику tree-sitter, мовний сервер та опціональну тему іконок. Встановіть його з менеджера розширень Zed:

1. Відкрийте палітру команд (`Cmd+Shift+P` / `Ctrl+Shift+P`)
2. Виконайте **zed: extensions**
3. Знайдіть `view.tree` або `mol` і встановіть розширення

Ви отримуєте підсвічування синтаксису, автодоповнення та структуру для файлів `.view.tree`. [Джерела](https://github.com/Dev-cmyser/zed-view.tree-mol-support) і відповідна [тема іконок](https://github.com/Dev-cmyser/zed-viewtree-icon-theme) на GitHub.

## VS Code

Робочий простір MAM уже несе своє налаштування VS Code. Коли ви відкриваєте склоновану папку `mam`, VS Code пропонує встановити рекомендовані розширення з `.vscode/extensions.json`:

- `nin-jin.vscode-language-tree` — підтримка мови `view.tree`
- `stan-donarise.view-tree-language` — синтаксис і граматика
- `editorconfig.editorconfig` — узгоджене форматування

Та сама папка постачає `mol.code-snippets`, тож сніпети компонентів і привʼязок доступні без жодного додаткового налаштування. Прийміть пропозицію — і файли `.view.tree` та TypeScript підсвічуються з коробки.

## Скіл для LLM

`mol_skill` дає AI-асистенту контекст, потрібний, щоб писати на $mol: синтаксис `view.tree`, будову MAM-модуля, поділ між `view.ts` і `view.css.ts`, моделювання даних у Giper Baza та пакування в Tauri. Це звичайна тека зі скілом — робочий процес `SKILL.md` плюс довідники, тож завантажити його може будь-який LLM-інструмент, що читає формат skills, зокрема Claude Code і Cursor. Встановіть його через CLI skills:

```bash
npx skills add b-on-g/mol_skill --all -g
```

Далі питайте своїми словами («будова MAM-модуля», «CRUD і ролі в Giper Baza»), і асистент відкриє потрібний довідник перед відповіддю, тож код відповідатиме домовленостям із цієї документації. [Вихідний код](https://github.com/b-on-g/mol_skill) лежить на GitHub, а самі довідники чудово читаються й окремо, якщо волієте пройтися ними самостійно.
