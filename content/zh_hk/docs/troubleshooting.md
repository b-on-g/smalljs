# 疑難排解

本頁每一條的形狀都一樣：建置是綠的，稽核是乾淨的，主控台一聲不吭，而畫面要麼空着，要麼不是你想要的樣子。編譯器看不見這些錯誤，因為每一個都是合法的程式，只不過它描述的是另一個元件。找到那條讀起來像你眼前現象的標題，下面就是原因和修法。

## 我覆寫了屬性卻沒有任何效果，也不報錯

`view.tree` 裏的名字和類別裏方法的名字不一致，最常見的是大小寫：樹裏寫 `exchange_form`，類別裏寫 `exchangeForm`。這是兩個屬性。類別裏的那個永遠不會被呼叫，樹裏的那個保持預設值，而且沒有任何東西會把這件事報出來。

名字處處都是 `snake_case`，而且必須逐字母一致。改過 `.view.ts` 之後，請檢查每一處覆寫是否仍然對應一個存在的屬性；樹旁邊產生的 `-view.tree/*.view.tree.d.ts` 就是用來比對的清單。

## 輸入框要設定 placeholder、停用狀態或輸入類型

這些都是 `$mol_string` 的屬性：`hint` 是 placeholder，`enabled` 是停用狀態，`type` 是輸入類型。在用到這個輸入框的地方設定它們：

```tree
<= Password $mol_string
	hint \Password
	type \password
	enabled <= can_edit true
	value? <=> password? \
```

任何其他元件的任何其他屬性都用同樣的方式找到：打開它的 `.view.tree`，正如[如何閱讀原始碼](#!section=docs/page=mental-model/Docs.Body=%E5%A6%82%E4%BD%95%E9%96%B1%E8%AE%80%E5%8E%9F%E5%A7%8B%E7%A2%BC)所示。

`attr *` 是給元件本身沒有建模的真實 DOM 屬性用的，它自己也有個坑：一個不以 `^` 開頭的區塊會整個替換掉基底類別的屬性字典，於是這樣寫的 `$mol_button` 會丟掉 `disabled`、`role` 和 `tabindex`。用 `^` 開頭來繼承，然後再加你自己的鍵：

```tree
attr *
	^
	data_kind \primary
```

## 一個詞被拆成一個個字母渲染出來

在期待清單的地方傳了一個字串，於是字串被逐字元攤開了。字串以 `\` 開頭，清單以 `/` 開頭。最常見的情形是 `sub`，它是一個清單：

```tree
sub / <= label \Hello
```

## 畫面是空的，測試卻是綠的

有一處覆寫從 `.view.ts` 裏掉了。樹給每個屬性都配了預設值，所以當類別不再重新定義 `rows()` 時，TypeScript 很滿意，而清單渲染出來是空的。只檢查模型的測試仍然是綠的，因為模型本身沒問題。

畫面依賴的每一處覆寫，都該寫一個讀取用戶所見之物的測試：`rows()`、`sub()`、子視圖的 `title()`，或者 DOM。[測試](#!section=docs/page=testing) 兩種都講了。

## 資料永遠載入不出來，元件卡在載入狀態

某個 `@ $mol_mem` 方法把 promise 當成值回傳了：`fetch( uri ).then( ... )`、一個 `async` 方法，或者 `$mol_wire_async( this ).load()` 的結果。單元裏的 promise 對所有人來說都讀作「仍在計算」，而當它解析時單元重新計算，又產出一個新的 promise。網絡是通的；視圖卻永遠等不到結果。

正確的形態是同步的：在單元裏呼叫 `this.$.$mol_fetch.json( uri )` 並回傳解析後的值。纖程會暫停直到回應到手，然後重跑這個單元，於是 promise 根本不會出現在你的程式碼裏。如果非同步的活兒必須發生在別處，把它的結果放進一個單獨的狀態單元，讓副作用回傳一個旗標或一個鍵，永遠不要回傳 promise。

第二個成因是被吞掉的錯誤：單元內部的 `try`/`catch` 把暫停連同真正的失敗一起捕捉了。請把任何屬於 `Promise` 的東西重新拋出，或者改用 `$mol_fail_catch`，它會替你做這個判斷。

## 循環訂閱

某個 `@ $mol_mem` 方法寫了另一個單元，或者做了副作用，結果讓它讀過的東西失效了。計算只讀取和回傳；寫入、網絡、計時器和 DOM 屬於 `@ $mol_action` 處理器。同一條訊息的另一個來源，是對某個子節點的 `<=>` 繫結，加上類別裏一個轉發給同一個子節點的方法，下一條就說這個。

## Maximum call stack 呼叫堆疊溢位

有兩種形狀會導致它。第一種，樹裏給子節點寫了 `tab? <=> tab?`，而類別裏寫了 `tab() { return this.Head().tab() }`：子節點問擁有者，擁有者又問子節點。去掉指向你所轉發的那個子節點的 `<=>`。

第二種，某個子視圖被重新指定成了你自己的類別，而類別在樹裏列出的某個屬性上呼叫了 `super`。那個 `super` 並不是基底類別的實作，而是樹為這條繫結產生的存根，而存根又轉發回擁有者。請明確地轉發給原本的實作，見下面關於重新指定型別的那一條。

## 大寫開頭的值無法從 TypeScript 覆寫

`<= Label* \` 產生的方法叫 `Label`，而類別裏的 `label()` 是另一個方法。子視圖首字母大寫，值首字母小寫，樹裏的大小寫決定了所產生方法的名字。

## 巢狀清單的每一列都顯示同一筆資料

巢狀在另一個帶鍵子視圖裏的帶鍵子視圖拿不到自己的鍵。`Row*0` 裏的 `Cell*0` 在每一列都用鍵 `0` 渲染。把列抽成一個獨立的元件，透過屬性把資料傳進去，並且把外層視圖寫成 `Row*` 而不是 `Row*0`。

## 我改了子視圖的類別，它的內容就消失了

把 `Pre* $mol_text_code` 重新指定為 `Pre* $my_code`，會丟掉基底類別的樹為它宣告的那些繫結，所以必須重新列一遍。而寫上 `text <= pre_text* \` 會造出一個空存根，把 `$mol_text` 真正的 `pre_text` 遮住。請在類別裏明確轉發，而不是指望 `super`——那個 `super` 就是那個存根：

```typescript
pre_text( index: number ) {
	return $mol_text.prototype.pre_text.call( this, index )
}
```

## 子類別上找不到基底元件 view.ts 裏的方法

樹裏的 `$my_child $my_base` 繼承的是由 `base.view.tree` 產生的類別，而不是你寫在 `base.view.ts` 裏的那個類別。定義在那裏的方法到不了子類別，TypeScript 會報告它們不存在。多個視圖共用的邏輯應該放進 `namespace $` 下的一個普通 `.ts` 檔案裏，不帶樹，就像 `$mol_view` 自己那樣寫。

## 宣告在同一個 view.tree 檔案裏的基底元件丟了自己的行為

當一個樹檔案同時宣告了基底類別和繼承它的類別時，基底類別的 `.view.ts` 主體對子類別會被跳過。帶 `.view.ts` 的基底元件，請給它自己的資料夾。

## 樣式在子視圖和它內部的元件之間串了

`$my_app` 裏的 `Nav $my_app_nav` 會把同一個 `my_app_nav` 屬性同時掛到子視圖和那個元件上，一條選擇器就命中兩個。給子視圖取一個不重複類別名尾巴的名字，比如 `Nav_row`。

## 針對 false 屬性的選擇器永遠匹配不上

值為 `false` 的布林屬性會從元素上被移除，所以 `[expanded="false"]` 甚麼都匹配不到。條件渲染不是 CSS 的活兒；覆寫那個子視圖的工廠方法，對不需要該視圖的變體回傳 `null`。

## 樣式裏寫了數字卻毫無變化

`style *` 裏的每個數字都會被加上 `px`：`flexGrow 1` 變成 `flex-grow: 1px`，瀏覽器直接丟棄。無單位的值請寫成字串，`flexGrow \1`。

## 捲動視圖的兩個子節點疊在了一起

`$mol_scroll` 只容納一個子節點。把這些子節點包進一個 `$mol_view` 或 `$mol_list`，再把它交給捲動視圖。

## minimal_height 看不出任何效果

`minimal_height` 是虛擬化的 `$mol_list` 在列渲染之前用來估算的數字，它並不設定高度。高度在 `.view.css.ts` 裏設定。

## 嵌入的元件把頁面撐得左右捲動

掛在別人版面裏的視圖，預設不會收縮到比自身內容更窄。在它的樣式裏給根節點加上 `minWidth: 0`，它才能像周圍的元素一樣被擠壓。

## 第三方 CSS 對我的元件不起作用

沒有 `dom_name` 的元件會渲染成一個以類別名命名的元素，對 CSS 框架來說那是一個未知的行內元素。請明確設定標籤：`$mol_button` 沒有設定，所以想讓外部 CSS 給它上樣式的按鈕需要 `dom_name \button`。

## 點擊指向當前頁面的連結反而清空了 URL

帶 `arg *` 的 `$mol_link` 是切換式的：在 URL 已經匹配的頁面上，點擊會把那些鍵移除。如果只想導覽，派生一個子類別並寫上 `uri_off <= uri`。如果想點擊時重新載入同一條路由，在處理器裏呼叫 `$mol_state_arg.value()` 並對事件 `preventDefault`。

## 我的輸入處理器每次渲染都會執行

你在 `$mol_string` 的子類別上新加的 `prop?`，和基底類別已經在用的某個屬性重名了：`enter`、`submit`、`hint`、`value`、`keyboard`。加新名字之前，先和基底類別的樹對一對。

## 我在 value 的 setter 裏拋出的錯誤從來不顯示

`$mol_string` 會捕捉 `value?` 拋出的例外，並把它交給輸入框的 `setCustomValidity`，所以它只會以瀏覽器原生的表單驗證形式出現。請透過你自己的渠道報告錯誤，比如一行狀態文字或一個訊息子視圖。

## 帶鍵的處理器繫結被報告為缺失

帶鍵子視圖上的 `event_click? <=> pick*? null` 不會為 `pick` 產生存根。請自己在樹的根部宣告 `pick*? null`，並在類別裏實作它。

## 打包結果裏出現了我從未用過的模組

建構器是靠掃描原始碼文字裏的 `$mol_name` 記號來找相依的，而字串字面量裏或 `/** */` 文件註解裏的記號，分量和程式碼裏的一模一樣。文件註解裏當作例子提到的一個名字，會把它整個模組拉進來，而故障會出現在一個你從沒碰過的檔案裏。寫例子和註解時請去掉 `$` 前綴，或者改寫成資料夾名。

## 下一步

這些問題大多歸結為一條規則：樹裏的名字就是契約，而編譯器只檢查型別，不檢查名字。[心智模型](#!section=docs/page=mental-model) 解釋了樹為甚麼是一份覆寫清單，[測試](#!section=docs/page=testing) 展示了那個能抓住沉默錯誤的測試。
