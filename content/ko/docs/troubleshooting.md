# 문제 해결

이 페이지의 모든 항목은 같은 모양입니다. 빌드는 초록이고, 감사는 깨끗하고, 콘솔은 조용한데, 화면은 비어 있거나 의도한 것과 다릅니다. 컴파일러가 이 실수들을 볼 수 없는 이유는, 하나하나가 유효한 프로그램이면서 다른 컴포넌트를 기술하고 있을 뿐이기 때문입니다. 지금 보고 있는 것과 비슷하게 들리는 제목을 찾으세요. 그 아래에 원인과 고치는 법이 있습니다.

## 프로퍼티 오버라이드가 아무 일도 하지 않는데 오류도 없다

`view.tree`의 이름과 클래스의 메서드 이름이 다릅니다. 대개는 대소문자 차이입니다. 트리에는 `exchange_form`, 클래스에는 `exchangeForm`. 이것은 두 개의 프로퍼티입니다. 클래스 쪽은 결코 호출되지 않고, 트리 쪽은 기본값을 지키며, 아무도 그것을 알려 주지 않습니다.

이름은 어디서나 `snake_case`이고 글자 하나까지 일치해야 합니다. `.view.ts`를 편집한 뒤에는 모든 오버라이드가 여전히 실재하는 프로퍼티를 가리키는지 확인하세요. 맞춰 볼 목록은 트리 옆에 생성되는 `-view.tree/*.view.tree.d.ts`입니다.

## 입력에 플레이스홀더나 비활성화, type이 필요하다

모두 `$mol_string`의 프로퍼티입니다. 플레이스홀더는 `hint`, 비활성 상태는 `enabled`, 입력 타입은 `type`. 입력을 사용하는 그 자리에서 설정하세요.

```tree
<= Password $mol_string
	hint \Password
	type \password
	enabled <= can_edit true
	value? <=> password? \
```

다른 어떤 컴포넌트의 다른 어떤 프로퍼티든 찾는 방법은 같습니다. 그 `.view.tree`를 여는 것, [소스를 읽는 법](#!section=docs/page=mental-model/Docs.Body=%EC%86%8C%EC%8A%A4%EB%A5%BC%20%EC%9D%BD%EB%8A%94%20%EB%B2%95)이 보여 주는 대로입니다.

`attr *`는 컴포넌트가 아직 모델링하지 않은 진짜 DOM 속성을 위한 것이고, 그 자체의 함정이 있습니다. 첫 줄이 `^`가 아닌 블록은 기반의 속성 딕셔너리를 통째로 대체하므로, 그렇게 쓴 `$mol_button`은 `disabled`, `role`, `tabindex`를 잃습니다. 상속하려면 블록을 `^`로 시작하고, 그다음에 여러분의 키를 더하세요.

```tree
attr *
	^
	data_kind \primary
```

## 한 단어가 글자 하나하나로 렌더링된다

리스트가 와야 할 자리에 문자열이 전달되어, 그 문자열이 글자 단위로 펼쳐졌습니다. 문자열은 `\`로 시작하고 리스트는 `/`로 시작합니다. 흔한 경우는 리스트인 `sub`입니다.

```tree
sub / <= label \Hello
```

## 화면은 비어 있는데 테스트는 초록이다

오버라이드가 `.view.ts`에서 빠졌습니다. 트리는 모든 프로퍼티에 기본값을 주므로, 클래스가 `rows()`를 다시 정의하기를 멈춰도 TypeScript는 만족하고 리스트는 비어 있는 채로 렌더링됩니다. 모델만 확인하는 테스트는 모델이 멀쩡하므로 초록으로 남습니다.

화면이 의존하는 모든 오버라이드에 대해, 사용자가 보는 것을 읽는 테스트를 쓰세요. `rows()`, `sub()`, 서브뷰의 `title()`, 또는 DOM입니다. [테스트](#!section=docs/page=testing)가 그 둘 다 보여 줍니다.

## 데이터가 끝내 로드되지 않고 컴포넌트가 로딩 상태에 갇힌다

`@ $mol_mem` 메서드가 promise를 값으로 반환했습니다. `fetch( uri ).then( ... )`, `async` 메서드, 또는 `$mol_wire_async( this ).load()`의 결과입니다. 셀 안의 promise는 모두에게 "아직 계산 중"으로 읽히고, 그것이 해결되면 셀은 다시 계산되어 새 promise를 만들어 냅니다. 네트워크는 동작하는데, 뷰는 결과를 한 번도 보지 못합니다.

올바른 모양은 동기적입니다. 셀 안에서 `this.$.$mol_fetch.json( uri )`를 호출하고 파싱된 값을 반환하세요. 파이버는 응답이 들어올 때까지 중단했다가 셀을 다시 돌리므로, promise가 여러분의 코드에 나타나는 일은 없습니다. 비동기 작업이 다른 곳에서 일어나야 한다면, 그 결과를 별도의 상태 셀에 넣고 이펙트는 플래그나 키를 반환하게 하세요. promise는 결코 반환하게 하지 마세요.

두 번째 원인은 삼켜진 오류입니다. 셀 안의 `try`/`catch`가 진짜 실패와 함께 중단까지 잡아 버리는 경우입니다. `Promise`인 것은 다시 던지거나, 그 검사를 대신해 주는 `$mol_fail_catch`를 쓰세요.

## 순환 구독(Circular subscription)

`@ $mol_mem` 메서드가 다른 셀에 썼거나, 자기가 읽었던 것을 결국 무효화하는 부수 효과를 일으켰습니다. 계산은 읽고 반환할 뿐입니다. 쓰기, 네트워크, 타이머, DOM은 `@ $mol_action` 핸들러에 속합니다. 같은 메시지의 또 다른 출처는 자식으로 가는 `<=>` 바인딩과, 바로 그 자식에게 위임하는 클래스의 메서드가 겹친 경우입니다. 다음 항목에서 설명합니다.

## Maximum call stack(호출 스택이 넘친다)

이것을 만드는 모양은 둘입니다. 첫째, 트리에서 자식에 `tab? <=> tab?`가 있고 클래스에 `tab() { return this.Head().tab() }`가 있는 경우입니다. 자식이 소유자에게 묻고, 소유자가 자식에게 묻습니다. 위임하는 그 자식으로 가는 `<=>`를 없애세요.

둘째, 서브뷰의 타입을 여러분의 클래스로 바꾸었는데 그 클래스가 트리에 나열된 프로퍼티에서 `super`를 호출하는 경우입니다. 그 `super`는 기반 구현이 아니라 나열된 바인딩을 위해 트리가 생성한 스텁이고, 스텁은 소유자에게 도로 위임합니다. 대신 원래 구현에 명시적으로 위임하세요. 아래의 타입 재지정 항목을 보세요.

## 대문자로 쓴 값을 TypeScript에서 오버라이드할 수 없다

`<= Label* \`는 `Label`이라는 이름의 메서드를 생성하므로, 클래스의 `label()`은 다른 메서드입니다. 서브뷰는 대문자, 값은 소문자이고, 생성되는 메서드의 이름을 정하는 것은 트리에서의 대소문자입니다.

## 중첩된 리스트의 모든 행이 같은 항목을 보여 준다

키가 있는 서브뷰 안의 또 다른 키가 있는 서브뷰는 자기 키를 받지 못합니다. `Row*0` 안의 `Cell*0`은 모든 행에서 키 `0`으로 렌더링됩니다. 행을 자체 컴포넌트로 옮기고 그 데이터는 프로퍼티로 넘기세요. 그리고 바깥 뷰의 키는 `Row*0`이 아니라 `Row*`로 붙이세요.

## 서브뷰의 클래스를 바꿨더니 내용이 사라졌다

`Pre* $mol_text_code`를 `Pre* $my_code`로 바꿔 달면 기반 트리가 그것에 대해 선언했던 바인딩이 떨어져 나가므로, 다시 적어 주어야 합니다. 그런데 `text <= pre_text* \`를 적으면 빈 스텁이 만들어져 `$mol_text`의 진짜 `pre_text`를 가립니다. 그 스텁인 `super`에 기대지 말고 클래스 안에서 위임하세요.

```typescript
pre_text( index: number ) {
	return $mol_text.prototype.pre_text.call( this, index )
}
```

## 기반 컴포넌트의 view.ts에 있던 메서드가 서브클래스에 없다

트리의 `$my_child $my_base`가 상속하는 것은 `base.view.tree`에서 생성된 클래스이지, 여러분이 `base.view.ts`에 쓴 클래스가 아닙니다. 거기서 정의한 메서드는 자식에게 닿지 않고, TypeScript는 없다고 보고합니다. 여러 뷰가 공유하는 로직은 트리가 없는 평범한 `.ts` 파일의 `namespace $`에 둡니다. `$mol_view` 자신이 그렇게 쓰여 있습니다.

## 같은 view.tree 파일에 선언한 기반 컴포넌트가 동작을 잃는다

하나의 트리 파일이 기반과 그것을 상속하는 클래스를 함께 선언하면, 자식에게는 기반의 `.view.ts` 본문이 건너뛰어집니다. `.view.ts`가 있는 기반에는 자체 폴더를 주세요.

## 서브뷰와 그 안의 컴포넌트 사이로 스타일이 샌다

`$my_app` 안의 `Nav $my_app_nav`는 서브뷰와 컴포넌트 양쪽에 같은 `my_app_nav` 속성을 붙이므로, 하나의 선택자가 둘 다 때립니다. 서브뷰에는 클래스 이름의 꼬리를 되풀이하지 않는 이름을 주세요. 예를 들어 `Nav_row`입니다.

## false인 속성을 노린 선택자가 결코 맞지 않는다

`false`로 설정된 불리언 속성은 요소에서 제거되므로, `[expanded="false"]`는 아무것과도 맞지 않습니다. 조건부 렌더링은 CSS의 일이 아닙니다. 서브뷰 팩토리를 오버라이드해서, 그런 뷰가 없는 변형에서는 `null`을 반환하세요.

## 스타일에 쓴 숫자가 아무것도 바꾸지 않는다

`style *` 안의 모든 숫자에는 `px`가 덧붙습니다. `flexGrow 1`은 `flex-grow: 1px`가 되고 브라우저는 그것을 버립니다. 단위가 없는 값은 문자열로 쓰세요. `flexGrow \1`입니다.

## 스크롤 뷰의 두 자식이 서로 겹친다

`$mol_scroll`은 정확히 하나의 자식만 담습니다. 자식들을 `$mol_view`나 `$mol_list`로 감싸고 그것을 스크롤에 주세요.

## minimal_height를 바꿔도 눈에 보이는 변화가 없다

`minimal_height`는 가상화된 `$mol_list`가 행을 렌더링하기 전에 어림잡는 데 쓰는 숫자이고, 높이를 설정하지 않습니다. 높이는 `.view.css.ts`에서 설정합니다.

## 끼워 넣은 컴포넌트가 페이지를 옆으로 밀어낸다

낯선 레이아웃 안에 마운트된 뷰는 기본적으로 자기 내용보다 작게 줄어들지 않습니다. 루트의 스타일에 `minWidth: 0`을 주어 주변 요소들처럼 눌릴 수 있게 하세요.

## 서드파티 CSS가 내 컴포넌트에 먹히지 않는다

`dom_name`이 없는 컴포넌트는 자기 클래스 이름을 딴 요소로 렌더링되고, CSS 프레임워크에게 그것은 알 수 없는 인라인 요소입니다. 태그를 명시적으로 설정하세요. `$mol_button`에는 `dom_name`이 없으므로, 바깥 CSS로 스타일을 입히고 싶은 버튼에는 `dom_name \button`이 필요합니다.

## 현재 페이지로 가는 링크를 클릭하면 URL이 지워진다

`arg *`를 가진 `$mol_link`는 토글입니다. URL이 이미 일치하는 페이지에서는 클릭이 그 키들을 지웁니다. 이동만 하는 링크를 원한다면 `uri_off <= uri`를 붙여 서브클래싱하세요. 클릭으로 같은 라우트를 다시 불러오려면, 핸들러에서 `$mol_state_arg.value()`를 호출하고 이벤트를 `preventDefault` 하세요.

## 입력 핸들러가 렌더링할 때마다 실행된다

`$mol_string`의 서브클래스에 추가한 `prop?`가 기반이 이미 쓰고 있는 프로퍼티와 같은 이름입니다. `enter`, `submit`, `hint`, `value`, `keyboard` 같은 것들입니다. 새 이름을 더하기 전에 기반 트리와 맞춰 보세요.

## 값 세터에서 던진 오류가 보이지 않는다

`$mol_string`은 `value?`에서 나온 예외를 잡아 입력의 `setCustomValidity`에 넘기므로, 네이티브 폼 검증으로만 나타납니다. 오류는 여러분 자신의 통로로 알리세요. 상태 줄이나 메시지용 서브뷰입니다.

## 키가 있는 핸들러 바인딩이 없다고 보고된다

키가 있는 서브뷰에 쓴 `event_click? <=> pick*? null`은 `pick`의 스텁을 생성하지 않습니다. 트리의 루트에 직접 `pick*? null`을 선언하고 클래스에서 구현하세요.

## 쓴 적 없는 모듈이 번들에 들어 있다

빌더는 소스 텍스트에서 `$mol_name` 토큰을 훑어 의존성을 찾고, 문자열 리터럴 안의 토큰이나 `/** */` 문서 주석 안의 토큰도 코드 안의 것만큼 똑같이 세어집니다. 문서 주석에 예시로 적은 이름이 그 모듈을 통째로 끌어오고, 그 탈은 여러분이 건드린 적 없는 파일에서 드러납니다. 예시와 메모는 `$` 접두사 없이 쓰거나, 대신 폴더 이름을 적으세요.

## 다음

여기 있는 것들 대부분은 하나의 규칙으로 귀결됩니다. 트리의 이름이 계약이고, 컴파일러는 타입은 검사해도 이름은 검사하지 않는다는 것입니다. 트리가 왜 오버라이드의 목록인지는 [멘탈 모델](#!section=docs/page=mental-model)이 설명하고, 조용한 실수를 잡아내는 테스트는 [테스트](#!section=docs/page=testing)가 보여 줍니다.
