# 릴리스

$mol은 **지속적으로** 전달됩니다. 번호가 매겨진 버전을 끊는 대신, 프레임워크는 [mam_mol](https://github.com/hyoo-ru/mam_mol) 모노레포에서 곧장 배포됩니다——병합된 모든 변경은 그것을 기반으로 빌드하는 누구에게나 즉시 사용 가능합니다. MAM 빌드 도구는 항상 현재 소스를 가져오므로, 업그레이드 단계도, 조율할 버전 매트릭스도 없습니다.

## 변경 따라가기

- **커밋 히스토리**——[mam_mol 커밋](https://github.com/hyoo-ru/mam_mol/commits/master)이 정본 변경 로그입니다.
- **모듈별 히스토리**——GitHub의 각 컴포넌트 폴더가 자체 커밋 로그를 지니므로, 여러분이 쓰는 부분만 지켜볼 수 있습니다.
- **DEV 커뮤니티**——주목할 만한 추가와 글은 [#mol 태그](https://dev.to/t/mol) 아래에서 공유됩니다.

## 이것이 실무에서 뜻하는 것

깨뜨리는 릴리스 경계가 없으므로, 프레임워크는 하위 호환적인 진화를 선호합니다: 컴포넌트는 이름을 바꾸지 않고 기능을 얻고, 타입이 있는 `view.tree` 인터페이스는 비호환을 런타임이 아니라 컴파일 타임에 드러나게 합니다. 업데이트 후 빌드가 컴파일되지 않으면, TypeScript 오류가 무엇이 바뀌었는지 곧바로 가리켜 줍니다.
